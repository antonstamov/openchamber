# Git-идентичности

Git-идентичность — это имя и почта, которые несут ваши коммиты, и способ, которым репозиторий входит на свой remote. Если вы работаете в личных и рабочих репозиториях, можно сохранить идентичности и применять нужную к каждому репозиторию. Управляйте ими в **Настройки → Git**.

## Добавление идентичности

1. Откройте **Настройки → Git** и выберите **Новая**.
2. Введите **имя пользователя** и **адрес электронной почты** для коммитов.
3. Выберите **способ аутентификации** — как она отправляет и забирает:
   - **Эта машина**: то, что Git на этой машине уже использует, например SSH-ключи, менеджер учётных данных или CLI `gh`
   - **Учётная запись**: выбранная **учётная запись контроля версий**, любая учётная запись, подключённая на карточке хоста в [Интеграциях](/ru/integrations/), например GitHub, GitLab, Gitea, Forgejo или Gerrit; отправки идут по HTTPS с токеном этой учётной записи
   - **SSH**: ключ, который OpenChamber хранит для этой идентичности
   - **Анонимно**: читает публичные репозитории по HTTPS без входа и не может отправлять
4. При желании дайте ей цвет и значок, чтобы её было легко узнать.

Ваша системная глобальная идентичность тоже показана, только для чтения.

В Gerrit идентичность учётной записи входит в Git с вашим именем пользователя Gerrit и HTTP-паролем, который вы подключили. Учётная запись GitHub Enterprise обслуживает задачи и запросы на слияние, но клонирование и отправка там идут через **Эту машину** или **SSH**.

## Применение идентичности к репозиторию

Выберите кнопку идентичности вверху [панели Git](/ru/git/) и выберите одну. Экраны добавления и клонирования предлагают тот же выбор. Идентичность, которая не может достичь репозитория, остаётся в списке выключенной с причиной: учётная запись на другом хосте, учётная запись или **Анонимно** на SSH-remote, либо SSH-ключ на HTTPS-remote.

Применение идентичности записывает её в **локальную** конфигурацию git этого репозитория, поэтому затрагивает только этот репозиторий, а ваша глобальная настройка остаётся как есть. Git в терминале и оболочке агента тоже её использует. **Системная идентичность** убирает написанное OpenChamber, и снова отвечает ваша собственная конфигурация Git.

## Парольные фразы SSH-ключей

Для зашифрованного SSH-ключа введите его необязательную парольную фразу перед **Поиском ключей в ~/.ssh**, затем подтвердите отпечаток и добавьте ключ. OpenChamber хранит ключ зашифрованным, а парольную фразу сохраняет в хранилище учётных данных OpenCode. Сохранённые парольные фразы работают только для действий Git в приложении. Команды Git в терминале и запускаемые агентом их не получают, поэтому зашифрованный управляемый ключ не может аутентифицироваться этим путём.
