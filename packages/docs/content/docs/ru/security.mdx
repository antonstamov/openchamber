# Безопасность

OpenChamber даёт доступ к вашей машине и коду, поэтому закройте его, прежде чем до него дотянется кто-то кроме вас. На этой странице — пароль интерфейса, ключи доступа и то, что нужно знать, прежде чем открывать OpenChamber в сеть.

## Установка пароля интерфейса

Запустите OpenChamber с паролем, и интерфейс в браузере будет его спрашивать:

```bash
openchamber --ui-password be-creative-here
```

Его можно также задать переменной окружения `OPENCHAMBER_UI_PASSWORD` вместо командной строки. После входа OpenChamber запоминает устройство на время, чтобы не спрашивать каждый раз.

Всегда задавайте пароль, если инстанс доступен кому-то ещё — особенно через [туннель](/ru/tunnels/) или публичный интернет.

## Ключи доступа

Когда пароль задан, можно добавить ключи доступа (Face ID, Touch ID, аппаратный ключ) для более быстрого входа. Добавьте их в **Настройки → OpenChamber → Ключи доступа**.

Ключи доступа привязаны к текущему паролю. Если вы меняете или убираете пароль, сохранённые ключи доступа стираются, и вы добавите их заново.

## Токены устройств

Устройства, сопряжённые через [Connect a Device](/ru/connect-devices/), аутентифицируются собственными токенами устройств, а не паролем интерфейса. Ссылки сопряжения одноразовые и истекают, если не использованы; каждое сопряжённое устройство перечислено в **Настройки → Удалённые инстансы → Connect to this server**, где любое из них можно отозвать в любой момент. Соединения вне дома идут через [Private Relay](/ru/private-relay/) со сквозным шифрованием, который не может читать ваш трафик.

## Прежде чем открывать

- По умолчанию OpenChamber слушает только вашу собственную машину (`127.0.0.1`). Чтобы слушать шире, нужно осознанное изменение, и сначала следует задать пароль.
- Для собственных устройств предпочитайте [сопряжение](/ru/connect-devices/) с [Private Relay](/ru/private-relay/) — тогда публично вообще ничего не открывается.
- Если нужен публичный URL, предпочитайте [туннель](/ru/tunnels/) или частную сеть (например VPN) открытию порта в интернет.
- Если ставите OpenChamber за собственный HTTPS-сервер, см. [Reverse Proxy](/ru/reverse-proxy/).

## Режим Enterprise

Если команде разрешено отправлять содержимое разговоров только настроенным вами в OpenCode провайдерам моделей, включите режим enterprise. Есть два способа, достаточно любого.

### Файл политики на машине

Этот способ — для управляемых вами ноутбуков. Положите файл с именем `policy.json` в папку, куда может писать только администратор:

| Система | Путь |
|---|---|
| macOS | `/Library/Application Support/OpenChamber/policy.json` |
| Windows | `C:\ProgramData\OpenChamber\policy.json` |
| Linux | `/etc/openchamber/policy.json` |

Путь не зависит от того, как установлен OpenChamber. Десктопное приложение, веб-сервер из npm, CLI и расширение VS Code читают один и тот же файл. Его можно раскатывать через менеджер устройств (Jamf, Intune и подобные). Для сервера в Docker смонтируйте файл по Linux-пути.

```json
{
  "enterpriseMode": true,
  "organization": "Acme",
  "relayUrl": "wss://relay.acme.com/ws",
  "allowNetworkAccess": false,
  "allowedExtensions": ["https://github.com/acme/"],
  "jev": {
    "url": "https://llm.acme.com/v1/systemone",
    "model": "acme-classifier",
    "apiKey": "..."
  }
}
```

Нужен только `enterpriseMode`. `organization` показывается в настройках как «Managed by Acme», чтобы люди знали, кто принял решение. `relayUrl` и `jev` фиксируют ваш собственный релей и вашу Jev-точку, `allowNetworkAccess` разрешает другим устройствам доступ к OpenChamber по сети, а `allowedExtensions` перечисляет доверенные репозитории расширений. Все они описаны ниже.

- Ничто, заданное пользователем в настройках или в окружении, не отключает то, что включил файл.
- Когда режим enterprise включает файл, решает только файл. Переменные окружения ниже для релея, Jev и доступа к сети игнорируются, потому что пользователь может задать их сам.
- Если файл существует, но не читается или не является валидным JSON, режим enterprise остаётся включённым и ничего не фиксируется. Настройки сообщают, что политику не удалось прочитать. Сломанный файл никогда тихо не снимает защиту.
- Изменения применяются без перезапуска.
- OpenChamber работает от имени пользователя, поэтому пользователь может читать файл. Помните об этом, прежде чем класть в него API-ключ.

### Переменная окружения

На сервере или в контейнере, где окружением управляете вы, этого достаточно:

```bash
OPENCHAMBER_ENTERPRISE_MODE=1
```

На ноутбуке это более слабый замок: десктопное приложение читает её из профиля login shell (например `~/.zshrc`), а пользователь может его править. Используйте там файл политики.

С переменной релей, Jev, доступ к сети и разрешённые расширения задаются собственными переменными: `OPENCHAMBER_RELAY_URL`, `OPENCHAMBER_JEV_URL`, `OPENCHAMBER_ALLOW_NETWORK_ACCESS=1`, `OPENCHAMBER_ALLOWED_EXTENSIONS` (URL репозиториев через запятую) и `OPENCHAMBER_ALLOW_LOCAL_EXTENSIONS=1`. В Docker понадобится сетевая, поскольку сервер должен слушать за пределами контейнера.

### Фиксация OpenCode CLI

Если на ваших машинах уже установлен OpenCode и OpenChamber должен использовать именно его, укажите его путь в файле политики. Работает и с режимом enterprise, и без него.

```json
{
  "opencodeBinary": "/usr/local/bin/opencode"
}
```

- OpenChamber запускает OpenCode только из этого пути. Он игнорирует путь в настройках, `OPENCODE_BINARY` и копию из состава десктопного приложения, которая остаётся на диске неиспользованной.
- Если по этому пути нет ничего запускаемого, OpenChamber не откатывается на другую копию. Он останавливается с ошибкой, называющей путь.
- Настройки показывают путь только для чтения, с пометкой, что его задал администратор.
- OpenChamber не устанавливает и не обновляет зафиксированный OpenCode и не объявляет новые версии. Обновления приходят с вашей раскаткой.
- CLI должен быть OpenCode 2.x, не старее требуемой OpenChamber версии. С более старым OpenChamber останавливается на экране «обновите OpenCode».
- Папка тоже подойдёт, если в ней лежит `opencode` (`opencode.exe` на Windows). Переменной окружения для этого нет, поскольку пользователь может задавать их сам.


### Скрытие встроенных каталогов навыков

OpenChamber поставляется с несколькими публичными каталогами навыков (Anthropic, OpenAI, Cursor, Matt Pocock). Если у организации есть собственный, добавьте его как пользовательский каталог и скройте встроенные в файле политики. Работает и с режимом enterprise, и без него.

```json
{
  "hideBuiltinSkillCatalogs": true
}
```

Тогда настройки предлагают только каталоги, добавленные людьми, и OpenChamber не загрузит встроенный, даже если попросить напрямую. Переменной окружения для этого нет, поскольку пользователь может задавать их сам.

### Примеры

Положите файл политики на Mac. Выполните в Terminal от имени администратора:

```bash
sudo mkdir -p "/Library/Application Support/OpenChamber"
sudo tee "/Library/Application Support/OpenChamber/policy.json" > /dev/null <<'JSON'
{
  "enterpriseMode": true,
  "organization": "Acme"
}
JSON
```

На Linux то же самое с папкой `/etc/openchamber`.

На Windows запустите PowerShell от имени администратора. Последняя строка оставляет папку доступной на запись только администраторам и системе:

```powershell
New-Item -ItemType Directory -Force "C:\ProgramData\OpenChamber" | Out-Null
@'
{
  "enterpriseMode": true,
  "organization": "Acme"
}
'@ | Set-Content -Encoding UTF8 "C:\ProgramData\OpenChamber\policy.json"
icacls "C:\ProgramData\OpenChamber" /inheritance:r /grant:r "Administrators:(OI)(CI)F" "SYSTEM:(OI)(CI)F" "Users:(OI)(CI)RX"
```

Сервер в Docker, добавленный в `environment` файла `docker-compose.yml`. Контейнер слушает за пределами себя, поэтому нужно разрешить доступ к сети:

```yaml
environment:
  OPENCHAMBER_UI_PASSWORD: ${OPENCHAMBER_UI_PASSWORD}
  OPENCHAMBER_ENTERPRISE_MODE: "1"
  OPENCHAMBER_ALLOW_NETWORK_ACCESS: "1"
  # Optional:
  OPENCHAMBER_RELAY_URL: wss://relay.acme.com/ws
  OPENCHAMBER_JEV_URL: https://llm.acme.com/v1/systemone
  OPENCHAMBER_JEV_MODEL: acme-classifier
  OPENCHAMBER_JEV_API_KEY: ${ACME_JEV_KEY}
  OPENCHAMBER_ALLOWED_EXTENSIONS: https://github.com/acme/
```

Чтобы проверить, что сработало, откройте Настройки → Провайдеры: вверху появится notice режима Enterprise с именем вашей организации.

### Что меняется

- Провайдеры моделей берутся только из вашего конфига OpenCode. Подключение провайдера, вход в него, добавление ключа или создание пользовательского провайдера в OpenChamber выключено; удаление или переключение уже существующих учётных записей по-прежнему работает. Это лишь закрывает путь через приложение; сам замок — политика OpenCode, описанная ниже. Вход в MCP-сервер из вашего конфига OpenCode по-прежнему работает, поскольку он обращается к тому серверу, а не к провайдеру моделей.
- [Classification providers (Jev)](/ru/classification-providers/) остаются выключенными, включая пользовательскую точку, введённую в настройках. Safety net и Auto не предлагаются, а сессии в работе не получают подсказку «looks done». Чтобы использовать Jev через собственную инфраструктуру, зафиксируйте точку ключом `jev` в файле политики либо через `OPENCHAMBER_JEV_URL` (плюс `OPENCHAMBER_JEV_MODEL` и, если ей нужен, `OPENCHAMBER_JEV_API_KEY`). Она станет значением по умолчанию, люди смогут её выключать, а выбрать что-то ещё — нет.
- Озвучивание через OpenAI выключено. Пользовательский сервер речи или транскрибации должен работать на той же машине. Локальные голоса и локальные модели диктовки продолжают работать.
- Push-уведомления на телефоны и в браузеры несут только общий заголовок вроде «Agent response is ready», без текста сообщения и имени сессии. Десктопные уведомления остаются на вашей машине и сохраняют полный текст.
- Проверки обновлений продолжают работать, чтобы до вас доходили исправления безопасности, но никогда не сообщают использование, даже анонимный ID установки.
- [Внешние туннели](/ru/tunnels/) (Cloudflare, ngrok, Tailscale) выключены. Cloudflare и ngrok расшифровывают трафик на своей границе и видят каждый запрос открытым текстом; Tailscale Serve и Funnel открывают эту машину другим устройствам.
- Диаграммы `.drawio` открываются как их XML-текст. Редактор диаграмм — собственная страница diagrams.net, и открытие диаграммы в нём передаёт ей файл.
- Каталог интеграций в боковой панели скрыт. Он устанавливает внешние сервисы из списка, поставляемого с OpenChamber. Добавление MCP-серверов, плагинов и навыков в настройках работает как раньше.
- Шрифты интерфейса и кода, грузящиеся с публичного CDN, откатываются на системные. Ваш выбор сохраняется на время, когда режим выключен.
- [Private Relay](/ru/private-relay/) работает только через ваш собственный релей. Запустите [self-hosted relay](https://github.com/openchamber/openchamber-relay) и укажите OpenChamber на него ключом `relayUrl` в файле политики или `OPENCHAMBER_RELAY_URL=wss://relay.example.com/ws`. Общий релей тоже не может читать ваш трафик, поскольку он сквозно зашифрован, но собственный держит метаданные соединений и путь в эту машину внутри вашей сети. Без собственного релея сопрягать устройства вообще нельзя.
- OpenChamber слушает только машину, на которой работает. Настройка десктопа, разрешающая другим устройствам в локальной сети открывать приложение, выключена, и сервер отказывается стартовать на сетевом адресе — через CLI (`--host`, `--lan`) или окружение. Если файл политики появляется, пока приложение работает, соединения с других машин разрываются до следующего запуска. Разрешите доступ к сети значением `"allowNetworkAccess": true` в файле политики или `OPENCHAMBER_ALLOW_NETWORK_ACCESS=1` там, где режим enterprise включается окружением. Помните, что соединение — обычный HTTP, поэтому в общей сети его может читать кто угодно; сервер, доступный другим, ставьте за [собственным HTTPS](/ru/reverse-proxy/).
- [Расширения](/ru/extensions/), способные отправлять данные с машины (говорящие с внешним API, грузящиеся с внешних адресов, запускающие фоновый сервис, получающие высказывания агента в сессиях этим сервисом, запускающие сессии, добавляющие инструкции или поставляющие навыки агентам), устанавливаются только из Git-репозитория, перечисленного в `allowedExtensions`. Разрешённое расширение, доставляющее уведомления, получает только общий заголовок, без текста сообщения, имени сессии или проекта — как телефон. Разрешённое расширение-трекер получает ваши поиски и идентификаторы открываемых элементов, а публикуемые им комментарии сессий несут фиксированную метку и ссылку на сессию, но никогда — сказанное в ней. Разрешённое расширение, сообщающее использование, получает учётные данные, которые OpenCode хранит для перечисленных в его манифесте провайдеров, которые вы подтвердили в его диалоге, и ничего из ваших сессий. Расширения, не делающие ничего из этого, устанавливаются как обычно. Установленное расширение из любого другого места остаётся выключенным, и настройки объясняют почему. Список содержит URL репозиториев, поскольку имя расширение выбирает себе само; запись с `/` на конце, например `https://github.com/acme/`, разрешает каждый репозиторий под ней. На машинах людей, собирающих расширения, `"allowLocalExtensions": true` также разрешает установку из локальной папки. ZIP остаётся закрытым в любом случае.
- Переменные окружения из **Настройки → Общие** и из `opencode service set env` не доходят до OpenCode, поскольку одна из них могла бы нести ключ провайдера. Git, терминалу и действиям проекта они по-прежнему достаются.
- В расширении VS Code подключение провайдеров выключено, а проверки обновлений не сообщают использование. В нём изначально нет Jev, релея, туннелей, push-уведомлений и облачной речи.

Задачи малой модели (заголовки сессий, итоги, сообщения коммитов, разбор диффа) особого режима не требуют. Они всегда работают на выбранной вами в настройках малой модели, либо на малой модели провайдера, с которым вы работаете, либо на модели по умолчанию из вашего конфига OpenCode. Они никогда не откатываются на другой подключённый у вас провайдер.

Какие провайдеры моделей вообще можно использовать, решает OpenCode, а не OpenChamber. Зафиксируйте это [политиками OpenCode](https://opencode.ai/v2/docs/policies/): запретите всех провайдеров, затем разрешите одобренные.

```jsonc
{
  "experimental": {
    "policies": [
      { "action": "provider.use", "resource": "*", "effect": "deny" },
      { "action": "provider.use", "resource": "anthropic", "effect": "allow" }
    ]
  }
}
```

Запрещённый провайдер исчезает, даже если для него добавить ключ. Поместите политики в глобальный `~/.config/opencode/opencode.jsonc`, где проект не может их снять, либо доставьте их из рабочего пространства OpenCode Console, у которого последнее слово. Режим Enterprise покрывает то, что поверх этого отправляет сам OpenChamber.

Веб-поиск агента и получение страниц тоже идут через OpenCode — к поисковому сервису и к самим страницам. Если им нельзя покидать вашу сеть, запретите их политикой того же вида:

```jsonc
{ "action": "permission", "resource": "websearch:*", "effect": "deny" },
{ "action": "permission", "resource": "webfetch:*", "effect": "deny" }
```
