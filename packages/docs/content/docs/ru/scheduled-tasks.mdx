# Запланированные задачи

Запланированная задача выполняет ваш промпт по расписанию — например, ежедневную сводку «что изменилось вчера» или еженедельную уборку. При срабатывании OpenChamber сам создаёт новую сессию и отправляет промпт. Планировщик открывается кнопкой вверху боковой панели сессий.

## Создание задачи

1. Откройте диалог запланированных задач из боковой панели сессий.
2. Добавьте задачу и дайте ей имя.
3. Выберите, когда она выполняется:
   - **daily** — в одно или несколько времён каждый день
   - **weekly** — в выбранные дни недели и время
   - **once** — один раз в указанную дату и время
   - **cron** — произвольное cron-выражение
4. Задайте, что она делает: промпт для отправки, а также провайдера, модель и агента. Промптом может быть slash-команда, например `/review`.
5. Сохраните и убедитесь, что задача включена.

Любую задачу можно выполнить сразу кнопкой **run now**, чтобы проверить, что она делает ожидаемое.

Отметьте **Run as goal**, чтобы запуск доводил промпт до завершения, а не останавливался после одного ответа — см. [Session Goals](/ru/session-goals/).

## Циклы: запланированные задачи как markdown-файлы

**Цикл** — это запланированная задача в виде переносимого markdown-файла, который можно коммитить в репозиторий. Положите файл в `.agents/loops/` и откройте список Scheduled Tasks для синхронизации — перезапуск сервера не нужен:

```markdown
---
name: daily-digest
schedule: "0 9 * * *"
enabled: true
model: anthropic/claude-sonnet-4-5
agent: plan
timezone: Europe/Kyiv
---
Summarize repository changes since yesterday and post the digest.
```

### Где живут файлы

- **Scope проекта** — `.agents/loops/*.md` в каталоге проекта или любом родительском каталоге вплоть до корня git worktree.
- **Scope пользователя** — `~/.agents/loops/*.md` применяется к каждому открытому проекту.

Если цикл проекта и цикл пользователя имеют одно имя, побеждает цикл проекта.

### Поля

| Поле | Значение |
|---|---|
| `name` | Имя задачи (обязательно, максимум 80 символов). |
| `schedule` | Cron-выражение (обязательно) — файлы циклов поддерживают только cron. |
| `enabled` | Установите `true` для запуска. Циклы **по умолчанию выключены**, поэтому коммит файла никогда не запускает задачу сам по себе. Цикл из репозитория ждёт, пока вы включите его в Scheduled Tasks на своей машине, а также после изменения его расписания, модели или промпта. Циклы в `~/.agents/loops` запускаются при одном лишь `true`. |
| `model` | `provider/model` (обязательно), например `anthropic/claude-sonnet-4-5`. |
| `agent` | Агент (необязательно). |
| `timezone` | IANA-часовой пояс (необязательно, по умолчанию — зона сервера). |
| body | Промпт выполнения (обязательно). Может быть slash-командой, например `/review src/`. |

### Как ведут себя циклы

- **Файл является источником правды**, пока существует. **Edit** открывает его во встроенном редакторе файлов, переключатель включённости обновляет его frontmatter, а удаление задачи удаляет markdown-файл после подтверждения. **Run now** остаётся доступным.
- Состояние выполнения (последний запуск, следующий запуск, статус) живёт в конфиге проекта и никогда не записывается обратно в markdown-файл.
- Переименование поля `name` переименовывает задачу на месте. Если файл цикла временно не парсится (правка в процессе, конфликт слияния), задача сохраняется с последним хорошим определением, пока файл не исправлен.
- Расписания `daily`/`weekly`/`once` и настройки целей остаются только в интерфейсе; файлы циклов — всегда cron.

## Как выглядит успех

После запуска задача показывает, когда выполнялась в последний раз, успешно ли, и ссылку на созданную сессию. Если запуск не удался, ошибка показана там же.

## Помните

Задачи срабатывают, только пока работает сервер OpenChamber. Если его закрыть, запланированные запуски приостанавливаются до его возвращения.
