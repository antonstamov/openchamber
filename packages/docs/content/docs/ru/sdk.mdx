# Создание расширения

Используйте `@openchamber/sdk`, чтобы добавить в OpenChamber собственную панель. Расширение — это небольшая веб-страница, которую OpenChamber показывает на правой панели. С приложением она общается через `connectHost()`: может читать текущий проект и сессию, показывать тосты, подставлять текст в поле чата, прикреплять задачу к сессии и — с согласия пользователя — запускать сессии и отправлять промпты.

Расширения работают в веб- и десктоп-версиях OpenChamber. VS Code и мобильные версии пока их не загружают.

## Что такое расширение

Папка из трёх файлов:

- `package.json` с блоком `openchamber` (манифест)
- `panel/index.html`, страница, которую показывает OpenChamber
- `panel/main.js`, ваш скрипт, собранный в один классический файл (IIFE, а не ES-модуль, потому что страница загружается в изолированном iframe)

OpenChamber никогда не компилирует ваш код. Поставляйте собранный `.js`-файл. SDK включает команду сборки; подойдёт и любой сборщик, выдающий IIFE.

```bash
npm install @openchamber/sdk
bunx openchamber-guest-bundle panel/main.ts panel/main.js
```

Команда сборки запускается на Bun. Без Bun используйте esbuild или любой другой сборщик с `--format=iife --platform=browser`.

Полностью рабочее расширение из всех трёх файлов — на странице [Example](/ru/sdk/example/). Скопируйте его и измените API и список.

Укажите `index.html` на `main.js` обычным `<script src="main.js"></script>`.

## Установка во время работы

1. Запустите OpenChamber в вебе или на десктопе.
2. Откройте Настройки → Расширения.
3. Вставьте абсолютный путь к папке и нажмите Add.

OpenChamber прочитает манифест и покажет диалог со списком того, что расширение просит (см. [Возможности](#возможности)). Подтвердите, и ваша иконка появится на панели. Нажмите её, и загрузится ваша страница.

Можно также добавить локальный `.zip` или https-ссылку на git-репозиторий либо zip-файл. Обновляться умеет только установка из git: поднимите `version` в `package.json` и запушьте, и OpenChamber проверит вскоре после открытия и затем каждые несколько часов, один раз сообщит пользователю и предложит обновление в Настройки → Расширения. Ссылка вида `openchamber://extensions/install?url=<encoded repository URL>` на любой странице открывает десктопное приложение с этим репозиторием в диалоге добавления, так что можно дать кнопку установки. `#tag` или `#branch` в URL фиксирует ветку, за которой следить. Они копируются в папку данных OpenChamber и запускаются из этой копии, поэтому поставляйте собранные файлы, а не `node_modules` или TypeScript-исходники. Удаление расширения удаляет копию. Установка из папки работает прямо из вашей папки, поэтому можно править, пересобирать и перезагружать.

## Манифест

```json
{
  "name": "@acme/hello",
  "version": "1.0.0",
  "openchamber": {
    "apiVersion": 1,
    "engines": { "openchamber": ">=1.24.0" },
    "id": "acme-hello",
    "name": "Hello",
    "icon": "window",
    "contributes": {
      "panel": { "entry": "panel/index.html" },
      "attach": "dialog",
      "page": true,
      "capabilities": ["prompt", "sessions"],
      "integration": {
        "name": "Acme",
        "description": "Tasks from Acme",
        "token": {
          "apiOrigin": "https://api.acme.example",
          "account": { "path": "/me", "name": "login" },
          "scheme": "bearer"
        },
        "settings": [{ "id": "list-id", "label": "List ID" }]
      }
    }
  }
}
```

`version` обязателен и должен быть semver. Настройки → Расширения показывают его на карточке.

`apiVersion` равен `1`. Любое другое значение OpenChamber отвергает.

`engines.openchamber` необязателен. Укажите самую старую версию OpenChamber, с которой работает расширение, как `1.24.0` или `>=1.24.0`. Более старые сборки откажутся устанавливать его, вместо того чтобы позже упасть.

`id`, `name` и `icon` называют расширение. `id` — в kebab-case и должен быть уникален среди установленных расширений. `icon` — имя Remixicon (`RiWindowLine` превращается в `window`) или SVG-файл внутри папки, например `icon.svg`. `contributes.panel` — панель расширения на боковой панели: её `entry` — HTML-файл внутри папки. Расширение без панели на панели опускает `panel`. Старые пакеты держат `id`, `name` и `icon` внутри `panel`, и это продолжает работать.

`contributes.attach` необязателен. Он добавляет расширение в меню + рядом с полем чата, чтобы пользователь мог выбрать задачу и прикрепить её к сессии.

- `"dialog"` — открывает вашу страницу в окне
- `true` или `"panel"` — открывает панель на боковой панели
- `{ "mode": "dialog", "entry": "panel/attach.html" }` — открывает в окне отдельную вашу страницу, чтобы выбор не делил код с панелью
- опустите — и расширение не попадёт в это меню

Ваша страница может узнать, где она находится, из `ctx.surface`: `panel`, `dialog`, `page`, `status` или `block`. Когда пользователь нажимает на прикреплённый элемент, его `data` приходит в `ctx.item`. Открытие с панели, из меню + или из полноэкранного меню страниц начинается без элемента.

`contributes.page: true` делает вашу панель доступной на весь экран из меню Extension pages над списком сессий. Используйте `{ "entry": "panel/page.html", "title": "Board" }` для отдельного HTML и необязательного заголовка. Поставьте этот HTML и его собранные скрипты. Странице нужны `panel.entry`, она использует ту же песочницу и разрешения и открывается только когда её выбирает пользователь. Перезагрузка, пауза, удаление или смена сервера её закрывают.

Для доски используйте `host.storage` для постоянного JSON и методы проекта/worktree/сессии для общих данных приложения. `startSession` может нацелиться на другой проект или worktree, не закрывая доску. См. [Host API](/ru/sdk/host/) про подписки, живые состояния и частичные результаты создания.

`contributes.integration` необязателен. Он добавляет карточку в Настройки → Интеграции, где пользователь подключает учётную запись. См. [Учётные записи и сеть](#учётные-записи-и-сеть).

`contributes.service` необязателен. Он объявляет локальный процесс, который OpenChamber запускает рядом с расширением, для того, до чего веб-страница не дотягивается, например Docker-сокета. Этот процесс работает с полным доступом пользователя и без песочницы, поэтому диалог подтверждения предупреждает об этом; объявляйте его только когда страница не справляется сама. См. файл пакета `GUEST_SERVICES.md`. Сервис с `provides: ["browser"]` может также подменять браузер агента: он отвечает на действия `browser.*` на сервере, и агенты ходят в интернет без открытого десктопного приложения, а пользователь выбирает его в Настройки → OpenChamber Tools. Такому сервису панель не нужна. Сервис также может узнавать, что происходит в сессиях пользователя: объявите рядом `contributes.sessionEvents`, и OpenChamber будет отправлять сервису каждый завершившийся или упавший ход и каждый запрос разрешения или вопрос агента, из каждого проекта, без открытого окна. См. [Session events](/ru/sdk/host/#события-сессий). А сервис с `provides: ["notifications"]` доставляет уведомления пользователя рядом с десктопом и телефоном, в Slack, Matrix или на ваш сервер; пользователь подключает учётную запись в Настройки → Интеграции, а токен остаётся в OpenChamber. См. [Notification channels](/ru/sdk/host/#каналы-уведомлений). Сервис с `provides: ["tracker"]` — это трекер рабочих элементов рядом с Linear, с карточкой учётной записи под Extension accounts; см. [Trackers](/ru/sdk/host/#трекеры). А сервис с `provides: ["quota"]` сообщает использование рядом со встроенными провайдерами, читая учётные данные, которые OpenCode хранит для перечисленных в манифесте провайдеров; см. [Usage providers](/ru/sdk/host/#провайдеры-использования).

## Возможности

Рисование панели и чтение текущей сессии разрешений не требуют. Всё, что действует от имени пользователя, — требует. Перечислите их в `contributes.capabilities`:

| Возможность | Что разрешает |
| --- | --- |
| `prompt` | отправлять сообщения в сессию пользователя (`prompt({ send: true })`, `startSession` с `text`) |
| `sessions` | перечислять проекты, worktree и состояния сессий; создавать и открывать сессии в зарегистрированных проектах |
| `files` | читать и писать файлы внутри открытого проекта (`readFile`, `writeFile`, `listDir`, `stat` с относительным путём) |
| `model` | разовая генерация текста малой моделью пользователя (`generate`), вне любой сессии |
| `shells` | следить за фоновыми shell-командами, запущенными вашими агентами, читать их вывод и останавливать их (`onRunningShells`, `readShellOutput`, `stopShell`) |

Ещё девять добавляются сами: `network`, когда объявлен `integration`, `service`, когда объявлен `service`, `filesystem`, когда объявлены шаблоны `filesystem`, `origins`, когда объявлены `origins`, `conversation`, когда действие сессии просит сообщения (см. [Действия, команды и значок](#действия-команды-и-значок)), `transcript`, когда `sessionEvents` или `sessionControl` просят `content` (см. [Session events](/ru/sdk/host/#события-сессий)), `sessionControl`, когда ваш сервис действует на сессии (см. [Calling OpenChamber](/ru/sdk/host/#вызов-openchamber-из-вашего-сервиса)), `instructions`, когда он добавляет к читаемому агентами, и `skills`, когда вы объявляете `contributes.skills`, папку навыков, попадающих каждому агенту, пока расширение включено.

Полный список пользователь видит один раз, при установке расширения, и подтверждает его либо удаляет расширение. Если новая версия просит больше, диалог появляется снова. Вызов, которому не хватает неподтверждённой возможности, завершается ошибкой `NOT_GRANTED`.

## Генерация текста

С возможностью `model` `host.generate` просит у Small Model пользователя разовый ответ: сводку, заголовок, черновик. Ничего не попадает в сессию, история не ведётся, и провайдера расширение не выбирает. OpenChamber использует ту же модель, что и для собственной фоновой работы, выбранную в Настройки → Сессии → Small Model, либо малую модель провайдера, с которым работает пользователь, либо модель по умолчанию из его конфига OpenCode.

```ts
const { text } = await host.generate({
  prompt: task.description,
  system: "Write a one-line summary. Return only the summary.",
  maxOutputTokens: 200,
});
```

Когда доступной модели нет, вызов завершается ошибкой `NO_MODEL`; модель, завершившаяся ошибкой, — `MODEL_FAILED`. Промпты ограничены 64 000 символов, а вызов ждёт до 960 секунд. Пользователь видит это разрешение как «Use your Small Model», и оно стоит ему токенов, поэтому делайте промпты короткими и вызывайте по клику, а не на каждое нажатие клавиши.

## Учётные записи и сеть

Ваша страница работает в песочнице и сама не может ходить в сеть: скрипты, стили, изображения, шрифты и медиа грузятся только из вашего пакета, а `fetch` достаёт только файлы вашего пакета. Поставляйте шрифты и изображения внутри пакета, а не грузите с CDN.

Чтобы говорить с внешним сервисом, объявите `integration`, и OpenChamber будет делать вызовы за вас через `host.request` с прикреплённым токеном пользователя. Токен никогда не попадает на вашу страницу.

Для всего остального, что нужно вашей странице напрямую, например шрифтов или изображений с CDN либо публичного API, перечислите до 8 https-источников:

```json
"origins": ["https://fonts.example.com"]
```

Пользователь видит их в диалоге подтверждения как адреса, которым расширение может отправлять данные и от которых получать, и подтверждает снова, если обновление добавляет новые. Подтверждённые источники открыты для `fetch`, изображений, шрифтов, стилей и медиа, но никогда для скриптов: код должен поставляться в вашем пакете. Источник страницы — `null`, поэтому чтобы прочитать ответ `fetch`, сервер должен разрешать CORS для этого источника.

В [enterprise mode](/ru/security/#режим-enterprise) расширение с `origins`, `integration` или `service` устанавливается только из Git-репозитория, перечисленного администратором. Если ваше расширение может работать без них, оно останется устанавливаемым для таких команд. Чтобы собрать его на такой машине, попросите у администратора `allowLocalExtensions`, разрешающий установку из папки.


- `token`: пользователь вставляет API-токен на карточке Настройки → Интеграции. `apiOrigin` — единственный источник, который может вызывать `request`. `account` необязателен: GET-путь и имя поля, чтобы карточка могла показать, кто подключён. `scheme` говорит, как отправляется токен; см. таблицу ниже. Каким заголовком его ждёт, смотрите в документации API провайдера.
- `oauth`: пользователь вставляет client id, и OpenChamber проводит authorize flow. Нужны `authorizeUrl`, `tokenUrl` и `apiOrigin`.
- `host: { "provider": "linear" }`: повторное использование уже подключённой в OpenChamber учётной записи Linear. Client id не нужен.

Что отправляет каждый `scheme`:

| `scheme` | Заголовок, который отправляет OpenChamber | Когда использовать |
| --- | --- | --- |
| опущен | `Authorization: <token>` | API документирует голый токен в заголовке |
| `"bearer"` | `Authorization: Bearer <token>` | API документирует bearer-токен или personal access token |
| `"basic"` | `Authorization: Basic base64(username:token)` | API документирует HTTP Basic auth с именем пользователя (часто email) и API-токеном; карточка спрашивает оба, а `usernameLabel` называет первое поле |

`settings` добавляет на карточку простые текстовые поля. Их значения приходят в `ctx.settings`. Поле с `"secret": true` маскируется на карточке и никогда не попадает на страницу; ваш сервис читает его через `readSettings()`.

## Файлы

Ваша страница сама не может трогать диск. OpenChamber читает и пишет за неё, в пределах одобренных пользователем лимитов.

- Относительный путь (`README.md`, `src/index.ts`, `.`) означает открытый проект. Нужна возможность `files`. Нет открытого проекта — `NO_DIRECTORY`.
- Путь с `/` или `~/` в начале означает anywhere else. Он должен совпасть с одним из шаблонов, объявленных вами в `contributes.filesystem`, и пользователь видит эти шаблоны в диалоге подтверждения:

```json
"filesystem": ["~/.config/opencode/opencode.json", "~/notes/**"]
```

Шаблоны используют `*` для одного сегмента пути и `**` для любой глубины. Всё вне их — `BAD_PATH`, даже после подтверждения. `..` никогда не разрешён.

```ts
const config = await host.readFile("~/.config/opencode/opencode.json");
await host.writeFile("~/.config/opencode/opencode.json", nextJson);
const { entries } = await host.listDir(".");
```

Записи атомарны: OpenChamber пишет во временный файл и переименовывает его, поэтому читатель никогда не видит полузаписанный файл. Файлы читаются и пишутся как UTF-8 текст, до 2 МБ.

## Раздел в Work Status

`contributes.statusSection` добавляет собственный раздел в панель Work Status рядом с чатом. Пользователи включают и выключают его и двигают в списке разделов панели, как встроенные разделы.

```json
"statusSection": { "entry": "status/index.html", "title": "Recent commits", "height": 160 }
```

- `true` повторно использует `panel.entry`.
- `entry` — отдельная HTML-страница в вашей папке. С ней `panel.entry` не нужен, поэтому расширение может быть только этим разделом, без иконки на панели.
- `title` заменяет имя панели в заголовке раздела, до 60 символов.
- `height` — стартовая высота в пикселях, от 24 до 320 (по умолчанию 120). Вызывайте [`host.setHeight()`](/ru/sdk/host/), когда меняется содержимое.

Ваша страница видит `ctx.surface` как `status`. OpenChamber загружает её, только пока видна панель Work Status и ваш раздел развёрнут, и выгружает, когда пользователь сворачивает раздел, поэтому не храните там ничего, что нельзя перестроить. Расширение только из раздела может использовать возможности, сервис, интеграцию и файлы, но не `page`, `attach`, `actions` или `commands`. Только веб и десктоп. Пример `git-graph-status` — готовый раздел.

## Редактор для вашего типа файлов

`contributes.fileEditors` открывает файлы в вашей странице вместо текстового редактора. Когда пользователь открывает подходящий файл в Files, OpenChamber показывает в нём ваш редактор, с тем же переключателем исходника, кнопками fullscreen и сохранения, что у встроенных просмотров.

```json
"fileEditors": [
  { "id": "canvas", "title": "Excalidraw", "match": ["*.excalidraw", "*.excalidraw.md"], "entry": "editor/index.html" }
]
```

- `match` сравнивает только имена файлов, без учёта регистра. `*` означает любой run символов, `?` — один. Шаблон не может содержать `/` и не может состоять только из масок.
- `entry` — HTML-страница в вашей папке. `panel.entry` не нужен, поэтому расширение может быть только редактором, без иконки на панели.
- `content` — `"text"` (по умолчанию) или `"binary"`, см. ниже.
- До 8 редакторов на расширение, до 16 шаблонов на каждый.

Файл ведёт OpenChamber. Ваша страница никогда его не читает и не пишет и не нуждается для этого в возможностях. OpenChamber передаёт вам текст, просит отредактированный текст при сохранении и берёт на себя Cmd/Ctrl+S, автосохранение, промпт о несохранённых изменениях, окончания строк и изменения на диске:

```ts
import { connectHost, createFileSaveTracker } from "@openchamber/sdk";

const host = connectHost();
let tracker = createFileSaveTracker(null);

host.onFileOpen((file) => {
  if (file.encoding !== "text") return; // a text editor always gets text
  load(file.content); // file.path, file.name, file.readOnly too
  tracker = createFileSaveTracker(versionOf(currentText()));
});

// Call this after every edit. `edited` holds autosave back until the user stops.
const changed = () => host.reportFileChange(tracker.observe(versionOf(currentText())));

host.onFileSnapshot(() => ({ content: currentText(), version: versionOf(currentText()) }));

// Edits made while OpenChamber was writing keep the file unsaved.
host.onFileSaved((version) => host.reportFileChange({ dirty: tracker.markSaved(version), edited: false }));
```

`version` — любая короткая строка, меняющаяся при изменении документа, например хэш. Если файл не из тех, что ваш редактор может открыть, вызовите `host.reportFileUnsupported()`, и OpenChamber покажет его исходник с заметкой. Файлы больше 20 МБ остаются в просмотре исходника.

### Бинарные файлы

Задайте `"content": "binary"`, чтобы открывать файлы, которые не являются текстом: таблицы, документы, изображения. Ваш редактор получает байты файла и отдаёт байты обратно; всё остальное работает так же.

```ts
host.onFileOpen((file) => {
  if (file.encoding !== "binary") return;
  open(file.bytes); // a Uint8Array, exactly as on disk
});

host.onFileSnapshot(() => ({ bytes: currentBytes(), version: versionOf(currentBytes()) }));
```

Бинарный редактор может заявлять любой файл, подходящий под его шаблоны, включая те, что OpenChamber превьюит сам, как изображения и PDF. У него нет просмотра исходника, и когда пользователь уводит его в fullscreen или возвращает обратно с несохранёнными изменениями, OpenChamber сначала их сохраняет. Чтение и запись формата — дело вашего редактора: OpenChamber записывает обратно ровно те байты, что вы вернули.

Ваша страница видит `ctx.surface` как `file`. OpenChamber перезагружает её, заново передавая файл, когда файл меняется на диске, пользователь отбрасывает изменения или редактор уходит в fullscreen или возвращается. Первое включённое расширение, чей шаблон совпал, побеждает, опережая собственные превью OpenChamber. Расширение только из редактора может использовать возможности, сервис, интеграцию и файлы, но не `page`, `attach`, `actions` или `commands`. Только веб и десктоп. Пример `checklist-editor` — готовый редактор.

## Действия, команды и значок

Помимо панели и меню + расширение может появляться ещё в трёх местах. Все они передают расширению `item` так же, как клик по чипу.

**Действия на сообщениях и сессиях.** Объявите пункты меню, и OpenChamber покажет их рядом со встроенными:

```json
"actions": [
  { "id": "create-task", "label": "Create task", "icon": "add-line", "where": "message", "roles": ["assistant"] },
  { "id": "summarize", "label": "Summarize session", "where": "session", "payload": ["messages"] }
]
```

`where` также принимает `selection` (текст, выделенный в сообщении), `file` (строка в Files) и `diff` (выбранные строки файла или диффа). Их элементы несут `kind` с тем же именем: `selection` — текст, `file` — путь, `diff` — путь и диапазон строк. На выделении `display` говорит, как показывать действие: `label` (по умолчанию), `icon` с подписью как подсказкой или `both`.

Действие сообщения открывает ваше расширение с `ctx.item` вида `kind: "message"`: id и заголовок сессии, каталог проекта, id сообщения, его роль и текст. Действие сессии открывает его с `kind: "session"` и id сессии, заголовком и каталогом. Добавьте `"payload": ["messages"]`, и элемент также понесёт весь разговор, от старых к новым, тем же текстом, что даёт экспорт в Markdown. Для этого нужна возможность `conversation`, которую пользователь видит отдельной строкой в диалоге подтверждения. `item.action` говорит, какой пункт нажали.

**Slash-команды, которые прикрепляют.** Объявите команду и обработайте её на странице:

```json
"commands": [{ "name": "task", "description": "Attach a task by id" }]
```

```ts
host.onResolve(async ({ command, args }) => {
  const task = await findTask(args.trim());
  return task ? { providerId: "acme-tasks", id: task.id, title: task.title, url: task.url } : null;
});
```

Когда пользователь вводит `/task ABC-12` в поле чата, OpenChamber просит ваше расширение разрешить её и прикрепляет возвращённое чипом, ничего не открывая. Верните `null` для «ничего не найдено». Если ваша панель закрыта, OpenChamber загружает её в фоне для вызова. Имя, уже используемое OpenChamber или OpenCode, игнорируется.

**Значок на иконке панели.** `host.setBadge(3)` ставит точку на вашу иконку и число в её подсказку, например открытых задач; `host.setBadge(null)` снимает её. Открытие панели тоже снимает её.

## Ваши инструменты в чате

Когда ваш плагин OpenCode или MCP-сервер добавляет инструмент, чат показывает его вызовы с общей иконкой и сырым выводом. Объявите, как они должны выглядеть, без кода:

```json
"tools": [
  {
    "match": "mcp.jira.*",
    "name": "Jira",
    "icon": "task-line",
    "title": "{input.key}",
    "subtitle": "{output.status}",
    "output": "table",
    "columns": ["key", "summary", "status"]
  }
]
```

`match` — имя инструмента, как его сообщает OpenCode; замыкающий `*` совпадает с префиксом. `icon` — имя Remixicon или `.svg`-файл в вашем пакете, как `panel.icon`. `title` и `subtitle` — шаблоны по `input`, `output` и `metadata` вызова. `output` выбирает, как рисовать тело: `text`, `json` (дерево), `markdown`, `code` с `language`, `table` с `columns` (строки — из массива вывода или `output.items`) или `auto` для стандартного. Точное совпадение `match` бьёт wildcard, а при ничьей побеждает первое установленное расширение. Разрешение не нужно: это лишь меняет отрисовку уже имеющихся в чате данных.

Расширению, только стилизующему инструменты, страница вообще не нужна: опустите `panel.entry`, и у него не будет иконки на панели, только карточка в Настройки → Расширения. Без страницы оно может объявлять `tools` и ничего больше. Другой исключение — раздел Work Status или редактор файлов с собственным `entry`, см. выше.

## Первые строки в панели

```ts
import { connectHost } from "@openchamber/sdk";

const host = connectHost();

host.onReady((ctx) => {
  document.body.dataset.theme = ctx.theme.mode;
  document.body.dataset.surface = ctx.surface;
});
```

`connectHost` работает только внутри OpenChamber. Открытый как обычный файл, каждый вызов отклоняется с `HOST_UNAVAILABLE`.

Стройте панель сначала из блоков `@openchamber/sdk/ui`: кнопки, поля, выпадающие списки, вкладки, списки и другое, в цветах и шрифтах приложения, чтобы панель ощущалась частью OpenChamber. Свой HTML и CSS пишите только для того, чего нет в наборе. См. [UI kit](/ru/sdk/ui/).
