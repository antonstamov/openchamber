# Host API

Используйте эту страницу, когда нужны точные методы `connectHost`, лимиты и коды ошибок. Расположение папок, манифест и установка — в разделе [Создание расширения](/ru/sdk/).

```ts
import { connectHost, HostRequestError } from "@openchamber/sdk";

const host = connectHost();
```

`connectHost` выбрасывает `HOST_UNAVAILABLE`, когда нет `window`. Вне OpenChamber он возвращает клиент, каждый вызов которого отклоняется с `HOST_UNAVAILABLE`. Вызовите `dispose()`, когда разбираете страницу; вызовы, ещё находящиеся в полёте, отклоняются с тем же кодом.

## Что OpenChamber отправляет вам

`onReady` срабатывает с первым снапшотом и снова при каждом обновлении его OpenChamber.

Это не одноразовый колбэк монтирования. Смонтируйте UI и подпишитесь один раз; используйте поздние снапшоты для обновления темы и контекста без замены вводов или черновиков. См. охраняемый пример в [UI-ките](/ru/sdk/ui/). Слушатели полей, такие как `onConnection`, воспроизводят текущее значение и могут получить его снова с обновлённым снапшотом. Сравнивайте поля, от которых зависят ваши данные, прежде чем начинать очередной запрос, и игнорируйте ответы от вытесненных запросов.

| Поле | Что это |
| --- | --- |
| `theme.mode` | `light` или `dark` |
| `theme.tokens` | цвета приложения (поверхности, текст, состояния взаимодействия, primary, success/warning/error/info), `font`, `mono` и `radius`. Передайте это в `applyHostReady` перед монтированием UI. |
| `locale` | тег языка приложения |
| `directory` | каталог текущего проекта или `null` |
| `session` | `{ id, title, busy }` или `null`. Заголовок откатывается к id сессии. `busy` — живой статус. `model` и `agent` (агент OpenCode) появляются, когда они есть у сессии. |
| `surface` | `panel` на панели, `dialog` в окне прикрепления, `page` на весь экран, `status` в панели статуса работы, `file` как редактор файлов в файлах, `block` в UI-блоке в чате |
| `item` | то, для чего открыта эта поверхность, или `null`: прикреплённый элемент, который кликнул пользователь (те же поля, что вы передали в `attach`, включая `data`), сообщение (`kind: "message"`) или сессия (`kind: "session"`) из одного из ваших объявленных действий. См. [Действия](/ru/sdk/#действия-команды-и-бейдж). |
| `connection` | `{ connected, account }` для вашей интеграции |
| `settings` | значения полей, объявленных вами в `integration.settings` |

Токены доступа никогда не появляются здесь или в результате `request`.

`onDirectory`, `onSession`, `onSessionLifecycle`, `onConnection`, `onSettings` и `onItem` воспроизводят последнее значение при поздней подписке, затем продолжают срабатывать по мере изменений.

`theme.tokens` включает `primaryText`, `successText`, `warningText`, `errorText` и `infoText`. Это обязательные поля с вычисленными хостом цветами текста для нейтральных фонов и тонированных контролов UI-кита, а не сплошных заливок. `applyHostReady` применяет их на каждом снапшоте. См. [UI-кит](/ru/sdk/ui/) для CSS-переменных.

## Методы

| Вызов | Что делает |
| --- | --- |
| `toast({ kind, message })` | показать тост в приложении. `kind` — `info`, `success` или `error`. |
| `openUrl(url)` | открыть URL; в десктопном приложении локальный адрес открывается в панели браузера рядом с чатом |
| `openSurface(surfaceId)` | показать тот экран, например `"git"` или собственную панель `"plugin:<panel id>"`. Разрешается, когда он на экране; уже открытый экран остаётся открытым. |
| `writeClipboard(text)` | скопировать текст. От 1 до 32000 символов. |
| `compose({ text, mode? })` | положить текст в поле чата без отправки. `mode` — `append` (по умолчанию) или `replace`. От 1 до 16000 символов после обрезки. |
| `attach({ ... })` | положить чип на поле чата, туда же, где элементы GitHub и Linear. Только один чип за раз. |
| `startSession({ ... })` | создать сессию с прикреплённым элементом. Возвращает `{ sessionId, sent }`. Нужна capability `sessions`. |
| `prompt({ text, send? })` | записать в текущую сессию или отправить в неё. Возвращает `{ sent }`. Отправка нуждается в capability `prompt`. |
| `sessionLink({ ... })` | прикрепить элемент к текущей сессии без её создания |
| `close()` | закрыть окно прикрепления. На панели ничего не делает. |
| `oauthStart()` | открыть страницу авторизации провайдера или страницу Linear для интеграции `host: { provider: "linear" }` |
| `oauthDisconnect()` | забыть сохранённый токен или соединение Linear |
| `request({ method, path, query?, body? })` | вызвать `apiOrigin` вашей интеграции с прикреплённым токеном пользователя |
| `serviceRequest({ method, path, query?, body? })` | вызвать локальный сервис вашего расширения (см. `GUEST_SERVICES.md`) |
| `serviceStatus()` | `stopped`, `starting`, `ready` или `failed` |
| `readFile(path)` | прочитать текстовый файл. Возвращает `{ content }`. |
| `writeFile(path, content)` | записать текстовый файл атомарно, создавая родительские папки. Возвращает `{ written: true }`. |
| `listDir(path)` | вывести каталог. Возвращает `{ entries: [{ name, kind }] }`, `kind` — `file`, `directory` или `other`. |
| `stat(path)` | `{ kind, size, mtime }`, `kind` — `file`, `directory`, `other` или `missing`. |
| `generate({ prompt, system?, maxOutputTokens? })` | разовый текст от малой модели пользователя. Возвращает `{ text }`. Нужна capability `model`. |
| `onResolve(handler)` | зарегистрировать обработчик ваших слэш-команд. Получает `{ command, args }` и возвращает прикрепляемый элемент или `null`. |
| `setBadge(count)` | пометить значок на панели точкой и положить число (от 0 до 999) в его подсказку, или `null`, чтобы очистить |
| `openCommit(sha)` | открыть представление Diff на этом коммите текущего проекта. `sha` — от 7 до 64 hex-символов; OpenChamber сам читает коммит. |
| `setHeight(px)` | задать высоту вашей секции статуса работы. OpenChamber держит её от 24 до 320 пикселей; более высокое содержимое прокручивается внутри вашей страницы. В остальных местах игнорируется. |
| `onFileOpen(listener)` | редакторы файлов: получить редактируемый файл, `{ path, name, readOnly }` плюс `encoding: "text"` с `content` или `encoding: "binary"` с `bytes`. Также заставляет Cmd/Ctrl+S на вашей странице сохранять. |
| `onFileSnapshot(handler)` | редакторы файлов: вернуть `{ content, version }` (или `{ bytes, version }` для бинарного редактора), весь отредактированный файл. OpenChamber вызывает это для сохранения и перед переключением на исходный вид или полноэкранный режим. |
| `onFileSaved(listener)` | редакторы файлов: снапшот с этим `version` — на диске. Ответьте `reportFileChange`. |
| `reportFileChange({ dirty, edited })` | редакторы файлов: сказать OpenChamber, есть ли несохранённые изменения и только ли что изменился документ |
| `requestFileSave()` | редакторы файлов: сохранить сейчас, как по Cmd/Ctrl+S |
| `reportFileUnsupported()` | редакторы файлов: этот файл здесь не открыть, показать вместо него его исходник |

## attach, startSession и sessionLink

Все три принимают одинаковые поля элемента:

```ts
await host.attach({
  providerId: "acme-hello",
  id: "TICKET-1",
  title: "Login is broken",
  url: "https://example.com/TICKET-1",
});

await host.attach({
  providerId: "acme-hello",
  id: "!12",
  title: "Fix login",
  url: "https://example.com/merge_requests/12",
  kind: "pull",
  author: "ada",
  branches: { head: "feature", base: "main" },
  text: "Optional notes for the model",
});

await host.startSession({
  providerId: "acme-hello",
  id: "!12",
  title: "Fix login",
  url: "https://example.com/merge_requests/12",
  kind: "pull",
  worktree: true,
  text: "Optional first message",
});
```

`providerId` — id вашей панели; OpenChamber всё равно перезаписывает его своим. `id` — ваш собственный идентификатор элемента. `kind` — `issue` (по умолчанию) или `pull`. `text` — необязательный контекст для модели, от 1 до 16000 символов после обрезки. `data` — необязательный собственный JSON (статус, комментарии, что угодно), до 16000 символов при сериализации. OpenChamber хранит его с чипом и возвращает без изменений в `ctx.item`, когда пользователь кликает чип; модели он никогда не передаётся.

`startSession` принимает `projectId` без переключения текущего проекта. Опустите `worktree` для целевого каталога, используйте `true` для сгенерированного worktree, `{ kind: "existing", directory }` для известного worktree или `{ kind: "new", name?, baseBranch? }` для именованного нового. Имя задаёт и ветку, и worktree. `navigation` по умолчанию `"preserve"`; используйте `"open"`, чтобы выбрать новый чат. Модель, агент и вариант первого сообщения фиксируются при старте создания.

Результат включает `sessionId`, `directory`, `sent`, `linked` и необязательный `worktree`. `sent` — `sent`, `no-model`, `skipped` или `failed`; `linked: false` означает, что элемент не был сохранён на созданной сессии. Worktree, оставшийся после неудачи bootstrap или создания сессии, возвращает `sessionId: null` и `failure: "bootstrap-failed" | "session-create-failed"`, плюс его каталог/worktree. Проверьте этот результат перед повтором. Вызов ждёт до 180 секунд; таймаут не означает откат создания.

`sessionLink` прикрепляет элемент к открытой сейчас сессии. Нет проекта или нет сессии — ошибка `NO_SESSION`.

Лимиты, применяемые клиентом до отправки:

| Поле | Максимум символов |
| --- | --- |
| `id` | 128 |
| `title` | 200 |
| `url` | 2000 |
| `text` | 16000 |
| `data` (сериализованный) | 16000 |
| `author` | 80 |
| каждое имя ветки | 200 |

## prompt и жизненный цикл сессии

```ts
await host.prompt({ text: "Fix the login" });
await host.prompt({ text: "Fix the login", send: true });

host.onSessionLifecycle((event) => {
  document.body.dataset.phase = event.phase;
});
```

Без `send` `prompt` заменяет текст поля чата. С `send: true` он отправляет сообщение с использованием выбранных пользователем модели и агента. Расширение их никогда не выбирает. Нет открытой сессии — `NO_SESSION`. Отправка, пока сессия занята, — `SESSION_BUSY`; запись в поле работает и при занятости. Результат — `{ sent }` с теми же значениями, что у `startSession`.

`onSessionLifecycle` сообщает, что делает сессия. `phase` — `started`, пока модель работает, `completed`, когда она простаивает, и `failure` при неожиданном статусе. Поздний слушатель сразу получает текущую фазу.

## Проекты, worktree и живые сессии

Эти методы используют существующее разрешение `sessions` и общие хранилища приложения. Они не выполняют git-сканирование на каждый запрос и не раскрывают содержимое разговоров.

```ts
const projects = await host.listProjects();
const projectId = projects.projects[0]?.id;
if (projectId) {
  const worktrees = await host.listWorktrees(projectId);
  const sessions = await host.listSessions(projectId);
  const stop = await host.onSessions(projectId, (snapshot) => {
    renderSessions(snapshot.sessions, snapshot.state);
  });
  // Call stop() when this view closes.
}
```

`onProjects(listener)` и `onWorktrees(projectId, listener)` работают так же. Дождитесь регистрации, чтобы поймать ошибки разрешений; результат — функция отписки. Каждая отправляет начальный снапшот, затем изменения. `dispose()` освобождает все подписки. Хост допускает не более 32 на кадр и очищает их при размонтировании, паузе, удалении или смене сервера.

Снапшоты имеют `state: "loading" | "ready" | "error"`. Загрузка/ошибка могут нести данные; только ready устанавливает полное пустое успешное завершение. Снапшоты сессий включают `coverage` по каталогам и известные архивированные сессии. Проекты раскрывают ID, имя и каталог; worktree — каталог, имя, ветку и доступность. Сессии включают свой проект/каталог/worktree, временные метки, родительский ID и ID/данные прикреплённых этим расширением элементов.

`activity` сессии — `unknown`, `idle`, `running`, `retrying`, `waiting-permission` или `waiting-question`. `outcome` — наблюдаемые `completed`/`failed` ход или `null`. Она не реконструируется из истории и хранится в памяти не более чем для 2000 наблюдаемых сессий. Простой после ошибки сохраняет failed-исход до следующего прогона. Ни idle, ни completed не помечают вашу задачу выполненной. Используйте `host.openSession(sessionId)` для явного перехода от карточки к её чату.

## Фоновые шеллы

С capability `shells` наблюдайте shell-команды, выполняющиеся в фоне, в охвате сессии и её субагентов, зарегистрированного проекта или каждой сессии. OpenChamber отвечает из локального хранилища; сетевого чтения не происходит.

| Вызов | Что делает |
| --- | --- |
| `onRunningShells(scope, listener)` | подписаться на shell-команды в охвате: `{ kind: 'session', sessionId }` покрывает сессию и её субагентов, `{ kind: 'project', projectId }` покрывает зарегистрированный проект, а `{ kind: 'global' }` покрывает каждую сессию. Вы получаете выполняющиеся команды от старых к новым, с их флагом `background`, и завершившиеся. Возвращает функцию отписки. |
| `readShellOutput(shellId, { cursor?, tailBytes? })` | одна страница вывода выполняющейся или завершённой команды. Без `cursor` она начинается за `tailBytes` (до 65536) до конца. Возвращает `{ output, cursor, skipped }`. |
| `stopShell(shellId)` | сначала отправить агенту заметку об остановке, затем убрать команду. |

Снапшот — `{ kind: "shells", scope, shells, ended }`, где `scope` повторяет охват подписки. Каждый выполняющийся шелл — `{ id, sessionID, command, startedAt, background }`, не более 200, от старых к новым. `background` — `true` для задачи, которую ход не ждёт.

`ended` перечисляет команды, завершение которых видел OpenChamber, от старых завершений к новым, не более 200 с сохранением новейших. Каждая добавляет `status`, `endedAt` и `exit`, когда команда завершилась с кодом. Статус — `exited`, `timeout`, `killed` по сигналу, `stopped` пользователем или `unknown`, когда конец случился во время переподключения. OpenChamber держит этот список только в памяти. После перезагрузки приложения он пуст, поэтому сохраняйте то, что показывает ваша панель, в хранилище расширения.

OpenCode хранит вывод завершённой команды для своих последних 25 завершённых команд на каталог. Остановленная команда сразу теряет вывод. Чтение шелла, которого OpenChamber никогда не видел, или вывода, которого у OpenCode больше нет, — `NOT_FOUND`. Так же и остановка не выполняющегося шелла. Неодобренная capability `shells` — `NOT_GRANTED`.

## Постоянные данные расширения

```ts
await host.storage.set("board", { columns: ["Todo", "Review"] });
const board = await host.storage.get("board");
const keys = await host.storage.keys();
await host.storage.delete("board");
```

Дополнительного разрешения не нужно. Хранилище принадлежит этому расширению на подключённом сервере, переживает перезагрузки и удаляется при удалении. `get` возвращает `undefined` для отсутствующего ключа; сохранённый JSON null остаётся null. Ключи — от 1 до 128 символов. Каждое сериализованное значение JSON — не более 64 КиБ UTF-8, а пространство имён — не более 2 МиБ или 2000 ключей. Используйте ID проекта в ключе для данных конкретного проекта. Записи сериализуются и атомарны; сбои сохраняют существующие данные.

## request

```ts
const user = await host.request({ method: "GET", path: "/api/v2/user" });
```

`path` начинается с `/` и не имеет схемы или хоста; OpenChamber соединяет его с `apiOrigin` из вашего манифеста и добавляет заголовок `Authorization`. Токен-интеграции отправляют вставленный токен как есть, как `Bearer <token>`, когда манифест задаёт `token.scheme: "bearer"`, или как `Basic base64(username:token)`, когда задаёт `"basic"`. OAuth- и Linear-интеграции всегда отправляют `Bearer`. Результат — `{ status, body }`. Тело — текст; разбирайте JSON сами.

Linear-интеграция также может делать `GET /api/linear/issues/get`, на который OpenChamber отвечает из собственного Linear-маршрута.

Нет ответа за 20 секунд — `HOST_TIMEOUT`.

```ts
try {
  await host.request({ method: "GET", path: "/api/v2/user" });
} catch (error) {
  if (error instanceof HostRequestError && error.code === "DISCONNECTED") {
    await host.oauthStart();
  }
}
```

## serviceRequest

Когда манифест объявляет `contributes.service`, OpenChamber запускает этот процесс, а ваша страница говорит с ним через вызов того же вида. Страница никогда не открывает сокет сама.

```ts
const status = await host.serviceStatus();
const result = await host.serviceRequest({ method: "GET", path: "/containers" });
```

`path` следует тем же правилам, что `request`. Объявление сервиса добавляет `service` в capability, одобряемые пользователем при установке; до этого каждый `serviceRequest` — `NO_SERVICE`. Полный контракт: файл пакета `GUEST_SERVICES.md`.

## События сессий

Ваша страница знает о сессии лишь пока она открыта. Ваш сервис может знать больше: объявите `contributes.sessionEvents` рядом с `contributes.service`, и OpenChamber отправляет перечисленные события в сервис, из каждого проекта, открыто ли окно или нет.

```json
"service": { "entry": "service/main.js", "runtime": "host" },
"sessionEvents": { "events": ["turn-finished", "question-asked"], "content": true }
```

События — `turn-started`, `session-created`, `session-archived`, `session-deleted`, `turn-finished` (агент done и ничего не ждёт: нет работающих субагентов, открытых разрешений или вопросов, шагов цели), `turn-failed`, `permission-asked` и `question-asked`. Ход, остановленный пользователем, ничего не отправляет. Одобрение расширения — это подписка; диалог перечисляет события под строкой сервиса. Без `content` сервис получает только идентификаторы: сессию, каталог её проекта, связанные с ней пользователем элементы. С `"content": true` манифест также запрашивает разрешение, которое пользователь видит отдельной строкой, **Читать то, что говорит агент, в фоне**, и каждое событие несёт финальный ответ агента, поля вопроса или детали разрешения.

Каждое событие приходит как один `POST /session-events` с сервисным bearer. Прочитайте его через `readSessionEventRequest` и ответьте `{ "ok": true }`:

```ts
import { SESSION_EVENTS_PATH, readSessionEventRequest } from "@openchamber/sdk";

// inside your service's request handler, after the bearer check
if (url.pathname === SESSION_EVENTS_PATH) {
  const request = readSessionEventRequest(body);
  if (!request) return json(res, 400, { ok: false, error: "not a session event" });
  const { event, content } = request;
  if (event.type === "turn-finished" && event.project.directory === myProject) {
    await postComment(event.linked, content?.type === "turn-finished" ? content.reply : "");
  }
  return json(res, 200, { ok: true });
}
```

События каждого проекта отправляются; сравнивайте `event.project.directory` с собственными настройками и отвечайте `{ "ok": true }` для остальных. Доставка — не более одного раза и по порядку, по одному запросу за раз; неудачный ответ роняет ваши события на 30 секунд, и ничего не переигрывается после простоя OpenChamber или вашего сервиса. Сервису не нужна панель для этого. Пример `session-events-log` журналирует каждое событие в файл.

## Вызов OpenChamber из вашего сервиса

Сервис может действовать без открытого окна. `createServiceHost` — его путь назад:

```ts
import { createServiceHost } from '@openchamber/sdk';

const host = createServiceHost({ env: process.env });

const { sessionId } = await host.sessions.start({ prompt: 'Summarize the failed deploy', directory });
await host.sessions.send(sessionId, 'Now write the incident note');
await host.setInstructions(directory, 'Deploys run through the release branch.');
await host.emit('deploy-finished', { id: 42 });
```

`sessions.start`, `sessions.send`, `sessions.retry` и `sessions.status` нуждаются в `contributes.sessionControl`, который пользователь одобряет отдельной строкой. `sessions.lastReply` нуждается в `sessionControl: { content: true }`. `setInstructions` нуждается в `contributes.instructions` и добавляется к тому, что читают агенты, в одной папке или, с `null`, везде.

`emit` достигает ваших открытых фреймов через `host.onServiceEvent`, поэтому панель перестаёт опрашивать. Ничего не переигрывается, поэтому фрейм, открывающийся позже, сначала читает текущее состояние. `readSettings` даёт сервису настройки интеграции, включая поля `secret`, а `needsConfiguration` показывает сообщение на карточке расширения.

## Работа, когда никто не просит

Сервис стартует по первому запросу, а сервис роли останавливается в простое. `service.keepRunning: true` запускает его вместе с OpenChamber и возвращает, когда он останавливается. `service.schedule` будит его по часам:

```json
"service": {
  "entry": "service/main.js",
  "runtime": "host",
  "keepRunning": true,
  "schedule": [{ "id": "nightly", "cron": "0 3 * * *", "timezone": "Europe/Kyiv" }]
}
```

Прогон — это один `POST /schedule`. Прочитайте его через `readServiceScheduleRequest` и ответьте 200. Прогон, пропущенный, пока OpenChamber был недоступен, потерян. Сервис, которому нужны внешние события, держит собственное соединение или опрашивает.

## Строки в меню @

`contributes.mentions: { label }` добавляет секцию в меню `@` композитора. Ваш сервис отвечает `POST /mentions/search` с `{ items: [{ id, title, subtitle?, url? }] }` в течение 2 секунд, и `POST /mentions/resolve` с `{ text }` для выбранной пользователем строки. Текст идёт агенту с сообщением, а пользователь видит чип. Медленный сервис не добавляет строк и никогда не задерживает файлы; строка, которую нельзя прочитать, не оставляет чипа и говорит об этом.

## Блоки в чате

`contributes.blocks` добавляет компоненты, которые агенты могут писать в UI-блоке. Ваша собственная страница рисует каждый, в той же песочнице и с теми же грантами, что ваша панель.

```json
"blocks": [{ "name": "JiraIssue", "description": "A Jira ticket", "args": ["key"], "entry": "blocks/issue.html" }]
```

Агент пишет `JiraIssue("OPE-1")`, а ваша страница читает вызов:

```ts
host.onBlock(({ args }) => draw(args.key));
```

Вызывайте `host.setHeight(px)` из `ResizeObserver` на вашем корне. Фрейм заполняет свой бокс без отступов, поэтому добавьте собственные. До 4 компонентов на расширение, поскольку каждая сигнатура — текст, который читает каждая сессия.

Блок может отвечать агенту, как кнопка в блоке. Вызовите `host.answerBlock(text)` по клику: агент получает текст и начинает следующий ход. Один ответ на блок, а `block.answered` хранит его после перезагрузки, поэтому рисуйте блок тогда как отвеченный.

```ts
host.onBlock(({ args, answered }) => draw(args.key, answered));
button.onclick = () => host.answerBlock('Close this ticket');
```

Задайте `"answers": true` на компоненте, который так делает. Агентам говорится спрашивать с ним вместо встроенного выбора, когда его описание подходит, а страница, ждущая ответа, опускает свою кнопку отправки. Под таким блоком OpenChamber предлагает то же поле заметки, что в собственных формах: агент читает заметку с вашим ответом, а заметка сама по себе — тоже ответ.

Аргументы пишет модель, поэтому текст с веб-страницы или тикета может ими управлять. Считайте их недоверенными и ничего не делайте с побочными эффектами, пока пользователь не кликнет.

## Каналы уведомлений

Сервис может доставлять уведомления пользователя, рядом с десктопом и телефоном: объявите `provides: ["notifications"]` и опишите канал в `contributes.notifications`.

```json
"service": { "entry": "service/main.js", "runtime": "host", "provides": ["notifications"] },
"notifications": {
  "label": "Slack",
  "instances": { "kind": "fixed", "origin": "https://slack.com" },
  "token": { "header": "authorization", "scheme": "bearer", "scopes": ["chat:write"] }
}
```

OpenChamber рисует карточку аккаунта для канала в разделе Настройки → Интеграции из этого описания и хранит аккаунт: пользователь подключает его там, токен остаётся в OpenChamber, а ваш сервис его никогда не видит. Когда аккаунт подключён, каждое уведомление, которое OpenChamber отправил бы на телефон, идёт и вашему сервису, после собственных переключателей уведомлений пользователя, и только пока не видно ни одного окна, если пользователь не выбрал уведомлять всегда. Пауза расширения останавливает это.

OpenChamber перенаправляет три вызова в `POST /notifications`: `auth.probe` (этот ли сервер — тот, куда вы доставляете), `auth.verify` (кому принадлежит этот токен) и `notify` (одно уведомление). Прочитайте каждый через `readNotificationsProviderRequest` и обращайтесь к серверу канала только через outbound-хелпер, который отправляет ваш запрос в OpenChamber с handle вызова; OpenChamber добавляет токен и держит запрос на сервере аккаунта.

```ts
import { NOTIFICATIONS_PROVIDER_PATH, createNotificationsOutbound, readNotificationsProviderRequest } from "@openchamber/sdk";

// inside your service's request handler, after the bearer check
if (url.pathname === NOTIFICATIONS_PROVIDER_PATH) {
  const request = readNotificationsProviderRequest(body);
  if (!request) return json(res, 400, { ok: false, error: { message: "not a notifications call" } });
  if (request.method === "notify") {
    const { notification } = request.input as { notification: GuestNotification };
    const answer = await outbound.request(request.session.handle, {
      method: "POST", path: "/api/chat.postMessage",
      headers: { "content-type": "application/json" },
      body: JSON.stringify({ channel: "#agents", text: `${notification.title}: ${notification.body}` }),
    });
    return json(res, 200, answer.status === 200 ? { ok: true, data: { delivered: true } } : { ok: false, error: { message: `Slack answered ${answer.status}`, status: answer.status } });
  }
  // auth.probe → { ok: true, data: { supported: true } }; auth.verify → { ok: true, data: { account: { id, login } } }
}
```

Какая комната или канал — для какого проекта, решает само расширение: уведомление несёт `directory` и `sessionName`. В корпоративном режиме оно несёт только общий заголовок, как телефон. Пример `notification-webhook` — полный канал с приёмником, чтобы попробовать.

## Трекеры

Сервис может быть трекером рабочих элементов рядом с Linear: объявите `provides: ["tracker"]` и опишите трекер в `contributes.tracker`. OpenChamber затем перечисляет его рядом с Linear везде, где появляются трекеры, из одного манифеста, ещё до запуска сервиса.

```json
"service": { "entry": "service/main.js", "runtime": "host", "provides": ["tracker"] },
"tracker": {
  "wire": 1,
  "label": "YouTrack",
  "instances": { "kind": "user", "label": "Server address", "placeholder": "https://youtrack.example.com" },
  "auth": { "token": { "header": "authorization", "scheme": "bearer", "createPath": "/users/me?tab=account-security" } },
  "capabilities": { "stateUpdate": true, "labels": true, "priority": true, "projectMapping": true, "sessionComments": true },
  "stateFilters": ["open", "all", "todo", "in-progress", "done"],
  "identifier": "key-number",
  "urls": { "item": ["/issue/{id}", "/{segments+}/issue/{id}"] }
}
```

Пользователь подключает аккаунты на карточке трекера под аккаунтами расширения: токен или вход через браузер, когда вы объявляете `auth.oauth` (OpenChamber выполняет вход с введённым пользователем client id и хранит токены). Ваш сервис никогда не видит credential. `urls.item` — шаблоны адреса элемента, с `{id}` для идентификатора (также как `?name={id}`, когда он едет в query); OpenChamber компилирует их, чтобы вставленные ссылки становились связанными элементами. `identifier` говорит, как выглядит ключ: `key-number` (`PROJ-42`), `number` или `short-code`.

OpenChamber перенаправляет девять вызовов в `POST /tracker`: `auth.probe` и `auth.verify`, чтения `items.list`, `items.get`, `items.liveSummaries`, `states.list` и `containers.list`, и записи `items.updateState` и `comments.create`. Прочитайте каждый через `readTrackerProviderRequest`, ответьте в нейтральных формах элементов и обращайтесь к серверу трекера только через outbound-хелпер, который отправляет ваш запрос в OpenChamber с handle вызова; OpenChamber добавляет credential и держит запрос на сервере аккаунта. Handle чтения отправляет только `GET`.

```ts
import { TRACKER_PROVIDER_PATH, createTrackerOutbound, readTrackerProviderRequest } from "@openchamber/sdk";

// inside your service's request handler, after the bearer check
if (url.pathname === TRACKER_PROVIDER_PATH) {
  const request = readTrackerProviderRequest(body);
  if (!request) return json(res, 400, { ok: false, error: { message: "not a tracker call" } });
  if (request.method === "items.get") {
    const answer = await outbound.request(request.session.handle, { method: "GET", path: `/api/issues/${encodeURIComponent(String(request.input.id))}` });
    if (answer.status === 404) return json(res, 200, { ok: true, data: { item: null } });
    if (answer.status !== 200) return json(res, 200, { ok: false, error: { message: `YouTrack answered ${answer.status}`, status: answer.status } });
    return json(res, 200, { ok: true, data: { item: toTrackerItem(JSON.parse(answer.body)) } });
  }
}
```

Когда пользователь включает комментарии сессий, OpenChamber вызывает `comments.create` с «session started», «completed» или «failed» и ссылкой на сессию, по одному разу каждое; комментарий не несёт ничего больше. Пример `tracker-provider` — полный трекер с фейковым сервером, чтобы попробовать.

## Провайдеры использования

Сервис может отчитываться об использовании рядом со встроенными провайдерами: объявите `provides: ["quota"]` и перечислите в `contributes.quota.providers` провайдеры OpenCode, чьи credential ему нужны. OpenChamber называет провайдера `ext-<panel.id>`, рисует его карточку с именем и значком расширения и спрашивает его так же, как встроенного.

```json
"service": { "entry": "service/main.js", "runtime": "host", "provides": ["quota"] },
"quota": { "providers": ["openrouter"] }
```

Диалог одобрения перечисляет эти провайдеры, а версия, меняющая список, спрашивает снова. При каждом обновлении OpenChamber отправляет один вызов, `usage.read`, в `POST /quota`, с `input.credentials`, содержащим credential, который OpenCode хранит для каждого перечисленного провайдера, у которого он есть (API-ключ или токены браузерного входа), и ничего больше из хранилища. Перечисленный провайдер, для которого у OpenCode нет credential, показывается как ненастроенный, и сервис не вызывается; пустой список допустим для провайдера, чей ключ живёт в собственных настройках расширения.

Прочитайте тело через `readQuotaProviderRequest` и ответьте `{ ok: true, data }` с результатом, который вычисляет встроенный: `ok`, `configured`, `error`, `planLabel` и `usage.windows` по именам окон, каждое с `usedPercent`, `windowSeconds`, `resetAt` (epoch-миллисекунды) и необязательными `valueLabel` или `value`, плюс `usage.models` для окон по моделям. OpenChamber выводит оставшуюся долю, обратный отсчёт до сброса и форматированные строки, чтобы карточка совпадала со встроенной.

```ts
import { QUOTA_PROVIDER_PATH, readQuotaProviderRequest } from "@openchamber/sdk";

// inside your service's request handler, after the bearer check
if (url.pathname === QUOTA_PROVIDER_PATH) {
  const request = readQuotaProviderRequest(body);
  if (!request) return json(res, 400, { ok: false, error: { message: "not a usage call" } });
  const credential = request.input.credentials.openrouter;
  const bearer = credential.type === "api" ? credential.key : credential.access;
  const answer = await fetch("https://openrouter.ai/api/v1/key", { headers: { authorization: `Bearer ${bearer}` } });
  if (answer.status === 401) return json(res, 200, { ok: true, data: { ok: false, configured: true, error: "OpenRouter refused the key.", usage: null } });
  return json(res, 200, { ok: true, data: toUsage(await answer.json()) });
}
```

Сервис отвечает в течение 20 с и останавливается после десяти минут без вызовов; страница использования обновляется каждые три минуты, пока открыта. Пример `quota-provider` — полный провайдер с фейковым API использования, чтобы попробовать.

## Файлы

Относительный путь — внутри открытого проекта и нуждается в capability `files`. Путь, начинающийся с `/` или `~/`, должен совпадать с объявленным шаблоном `contributes.filesystem` и нуждается в capability `filesystem`. Правила см. в [Создании расширения](/ru/sdk/#файлы).

```ts
const { content } = await host.readFile("package.json");
await host.writeFile("notes/today.md", "# Today\n");
const { entries } = await host.listDir("src");
const info = await host.stat("~/.config/opencode/opencode.json");
```

Лимиты: путь до 1024 символов, содержимое до 2 000 000 символов, листинг до 2000 записей. Превышение лимита содержимого — `FILE_TOO_LARGE`.

## generate

```ts
const { text } = await host.generate({ prompt: notes, system: "Summarize in one sentence." });
```

`prompt` — от 1 до 64 000 символов после обрезки, `system` — до 8000, `maxOutputTokens` — от 1 до 4000. Ничего не попадает в сессию, история не ведётся; расширение никогда не выбирает модель. Вызов ждёт до 960 секунд. Нет пригодной малой модели — `NO_MODEL`; ошибка модели — `MODEL_FAILED`. См. [Генерация текста](/ru/sdk/#генерация-текста).

Пользователь может закрыть вашу панель или переключиться на другой проект до прихода ответа. Генерация всё равно завершается, а приложение хранит ответ для вашей следующей панели на той же поверхности и в том же проекте, в том же окне. Зарегистрируйте `onLateGenerateResult`, чтобы получить его там:

```ts
host.onLateGenerateResult((late) => {
  if (late.ok) showSummary(late.request.prompt, late.result.text);
  else showError(late.error);
});
```

`late.request` — то, что отправила закрытая панель, чтобы можно было понять, на какой запрос отвечает. Каждый ответ приходит один раз. Приложение хранит ответы час, не более 8 на расширение, и роняет их при отключении или удалении расширения. Перезагрузка всего приложения или другое окно начинают пустыми. Приложения, не хранящие поздние ответы, не задают `ready.features.lateGenerateResults` и никогда не вызывают слушатель.

## Коды ошибок

Неудачные вызовы выбрасывают `HostRequestError`. `code` — один из этих; `message` говорит больше.

| Код | Когда |
| --- | --- |
| `HOST_UNAVAILABLE` | нет окна, не внутри OpenChamber, или выполнился `dispose()` |
| `HOST_TIMEOUT` | нет ответа за 20 секунд |
| `HOST_REJECTED` | OpenChamber отказал или ответил кодом, которого этот SDK не знает |
| `DISCONNECTED` | нет токена или соединения Linear для вашей интеграции |
| `BAD_PATH` | `path` был malformed или пытался выйти за разрешённый origin |
| `NO_INTEGRATION` | в манифесте нет `integration` |
| `NO_SESSION` | `prompt` или `sessionLink` без открытой сессии |
| `SESSION_BUSY` | `prompt({ send: true })`, пока сессия была занята |
| `DISABLED` | пользователь поставил расширение на паузу в разделе Настройки → Расширения |
| `NO_SERVICE` | сервис не объявлен, не одобрен или не запущен |
| `NOT_GRANTED` | пользователь не одобрил capability, нужную этому вызову |
| `SERVICE_FAILED` | сервис упал или так и не стал ready |
| `NO_DIRECTORY` | относительный путь к файлу использован без открытого проекта, `openCommit` без открытого проекта или `openSurface` до открытия чата или проекта |
| `NOT_FOUND` | `readFile` для несуществующего файла или `openCommit` для коммита, которого нет в проекте |
| `FILE_TOO_LARGE` | содержимое файла сверх лимита, на чтении или записи |
| `DENIED` | операционная система отказала в файловой операции |
| `NO_MODEL` | `generate` без доступной малой модели |
| `MODEL_FAILED` | малая модель вернула ошибку |
| `UNSUPPORTED` | этот OpenChamber не умеет вызов, например `openCommit` там, где нет представления Diff, или `openSurface` для экрана, который там не открыть |
