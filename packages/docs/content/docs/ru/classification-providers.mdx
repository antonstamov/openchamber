# Провайдеры классификации (Jev)

Некоторым функциям OpenChamber нужно быстрое решение перед действием: рискованна ли эта команда, к какому типу задач относится этот запрос, похожа ли эта работа на законченную? На эти вопросы отвечает небольшая решающая модель Jev (от TypeSafe). Эта страница показывает, как дать OpenChamber доступ к Jev.

Jev никогда не пишет код и не отвечает в вашем чате. Он только возвращает вердикт, а OpenChamber действует по нему. OpenChamber ждёт ответа не дольше четырёх секунд.

## Что использует Jev

| Функция | Вопрос, на который отвечает Jev |
| --- | --- |
| [Разрешения и страховочная сетка](/ru/permissions/) | Спросить ли вас перед выполнением этого действия? |
| [Автоматическая маршрутизация моделей](/ru/auto-model-routing/) | К какой из ваших категорий относится этот запрос? |
| [Сессии в работе](/ru/sessions-in-work/) | Похож ли этот шаг на конец работы? |
| [Итог сессии и предложение](/ru/sessions-in-work/#итог-и-предложение-следующего-сообщения) | Стоит ли генерировать итог или предлагаемое следующее сообщение после этого шага? |

Без провайдера страховочная сетка и «Авто» скрыты, а сессии в работе не получают подсказку «похоже на конец». Сессии всё равно попадают в работу, когда вы отправляете сообщение. Итоги и предложения по-прежнему работают, просто без фильтра.

## Настройка

Jev выключен, пока вы его не включите: ничего из ваших бесед не уходит провайдеру классификации, пока вы его не выберете. Откройте **Настройки → Провайдеры → Провайдеры классификации** и выберите, куда пойдут запросы к Jev. Кроме **Выкл**, есть шесть вариантов.

### Промоакция OpenCode Zen

Бесплатно в течение ограниченного времени, ключ не нужен. OpenCode позволяет OpenChamber использовать Jev через OpenCode Zen без оплаты, пока действует промоакция.

Когда промоакция закончится, вариант исчезнет, и OpenChamber переключится на один из ключей ниже, если он у вас есть.

### Ключ OpenCode Zen

Использует ключ Zen API, сохранённый в OpenCode, с оплатой с вашего баланса Zen.

1. Откройте **Настройки → Провайдеры** и добавьте ключ API в провайдер **OpenCode Zen** (см. [Провайдеры, модели и агенты](/ru/providers/)).
2. Вернитесь в **Провайдеры классификации** и выберите **Ключ OpenCode Zen**.

Входа через учётную запись OpenCode недостаточно. Для Jev Zen принимает только ключ API.

### Ключ OpenRouter

Использует ключ OpenRouter API, сохранённый в OpenCode, с оплатой на ваш счёт OpenRouter. Если вы уже используете модели OpenRouter в OpenCode, настраивать ничего не нужно. Подойдёт и ключ в переменной окружения `OPENROUTER_API_KEY`. Если есть оба, побеждает ключ, сохранённый в OpenCode.

1. Откройте **Настройки → Провайдеры** и добавьте ключ API в провайдер **OpenRouter**.
2. Вернитесь в **Провайдеры классификации** и выберите **Ключ OpenRouter**.

### Ключ Vercel AI Gateway

Использует ключ AI Gateway API, сохранённый в OpenCode, с оплатой на ваш счёт Vercel. Подойдёт и ключ в переменной окружения `AI_GATEWAY_API_KEY`. Если есть оба, побеждает ключ, сохранённый в OpenCode.

1. Откройте **Настройки → Провайдеры** и добавьте ключ API в провайдер **Vercel AI Gateway**.
2. Вернитесь в **Провайдеры классификации** и выберите **Ключ Vercel AI Gateway**.

### Ключ TypeSafe API

Ваш собственный ключ и квота TypeSafe.

1. Получите ключ API на [TypeSafe](https://docs.typesafe.ai).
2. Вставьте его в поле **Ключ TypeSafe API** и нажмите **Сохранить**.

Сохранение ключа также выбирает его. Ключ хранится на сервере OpenChamber в собственном файле и никогда не отправляется в браузер.

### Свой эндпоинт

Любой сервис, говорящий на System One API от TypeSafe: собственный шлюз, корпоративный прокси или провайдер, которого нет в списке.

1. В разделе **Свой эндпоинт** заполните **URL эндпоинта** и **Модель** (например, `jev-latest`).
2. Добавьте **ключ API**, если сервис его требует. Он отправляется как токен `Bearer`.
3. Нажмите **Сохранить**.

Вставьте полный адрес, на котором отвечает сервис, например `https://api.typesafe.ai/v1/systemone` или корпоративный прокси `https://proxy.company.internal/v1/decision`. OpenChamber вызывает его ровно так, как вы вставили, ничего не добавляя к пути. Работают только `http` и `https`, а ключ указывается в собственном поле, никогда — в URL.

Сохранение также выбирает эндпоинт. Как и ключ TypeSafe, эндпоинт и его ключ хранятся на сервере OpenChamber в собственном файле, а ключ никогда не отправляется в браузер.

Сервер может также получить эндпоинт из окружения — это удобно, когда вы настраиваете OpenChamber для команды:

```bash
OPENCHAMBER_JEV_URL=https://jev.example.com/v1/systemone
OPENCHAMBER_JEV_MODEL=jev-latest        # optional, this is the default
OPENCHAMBER_JEV_API_KEY=...             # optional
```

На управляемых вами ноутбуках укажите тот же эндпоинт под `jev` в [файле политики](/ru/security/#файл-политики-на-машине) на машине. Он побеждает окружение.

В любом случае он заменяет эндпоинт, сохранённый в настройках, и настройки показывают его без возможности редактирования. В [корпоративном режиме](/ru/security/#корпоративный-режим) это единственный разрешённый источник Jev кроме **Выкл**, и он выбран по умолчанию.

Карточка в **Настройки → Провайдеры** показывает **Готово**, когда провайдер работает.

## Когда ваш выбор перестаёт работать

Если выбранный провайдер недоступен (промоакция закончилась, ключ удалён), OpenChamber переключается на первый работающий из ваших собственных ключей: сначала ключ TypeSafe, затем свой эндпоинт, затем OpenRouter, затем Vercel AI Gateway, затем ключ Zen. На промоакцию отката никогда не бывает, а **Выкл** остаётся выключенным. Страница сообщает, какой из них используется прямо сейчас.

Если Jev тормозит или не справляется с отдельным запросом, ничего не ломается. У каждой функции есть безопасный ответ на этот случай:

- Страховочная сетка оставляет действие в ожидании вас.
- «Авто» отправляет запрос вашей резервной модели.
- Подсказка «похоже на конец» на сессиях в работе не появляется.
- Итог и предложение генерируются так, будто Jev нет.

## Что видит Jev

Jev получает короткие отрывки вашей беседы: ваше последнее сообщение, а для контекста — до трёх предыдущих реплик, обрезанных до первых нескольких сотен символов. Для страховочной сетки он также получает проверяемое действие в том виде, как его описывает OpenCode: команду, которую хочет выполнить агент, или файл и изменение для правки. Целых файлов и изображений он никогда не получает.

Запросы идут с сервера OpenChamber напрямую в OpenCode Zen, OpenRouter, Vercel AI Gateway, TypeSafe или на ваш эндпоинт — в зависимости от вашего выбора.

## Где это работает

Jev выполняется на сервере OpenChamber, поэтому работает в приложении для компьютеров, в веб-приложении и на телефоне, подключённом к любому из них. Расширение VS Code общается с OpenCode напрямую и не имеет Jev: там нет страховочной сетки, «Авто» и подсказки «похоже на конец».
