# Разрешения и страховочная сетка

Каждое действие агента (запуск команды, редактирование файла, вызов MCP-инструмента, получение страницы) сначала проходит через правила разрешений агента. Режимы разрешений OpenChamber определяют, что происходит, когда правило говорит «спросить».

## Разрешить, спросить и запретить

Правила разрешений живут в OpenCode. Каждое правило даёт действию один из трёх эффектов:

- **разрешить:** агент идёт дальше
- **запретить:** действие блокируется
- **спросить:** агент останавливается и ждёт ответа

Из коробки большинство действий разрешены. OpenCode спрашивает, только прежде чем агент тронет папки вне проекта или прочитает файлы `.env`. Добавьте собственные правила, чтобы спрашивать, например, перед любой shell-командой. Формат правил см. в [разрешениях в документации OpenCode](https://opencode.ai/v2/docs/permissions/), а разрешения агента в OpenChamber — в **Настройки → Агенты**.

Режимы разрешений меняют только то, кто отвечает на «спросить». Они никогда не разблокируют «запретить», а «разрешить» и так никогда не спрашивает.

## Три режима

| Режим | Кто отвечает на «спросить» |
| --- | --- |
| **Спрашивать каждый раз** | Вы. Каждый запрос ждёт вашего ответа. |
| **Страховочная сетка** | Jev пропускает рутинные действия и оставляет рискованные вам. |
| **Принимать всё** | OpenChamber, всегда да. Каждый запрос разрешается сразу, без проверок. |

**Принимать всё** ничего лишнего не требует: оно просто считает каждое «спросить» разрешённым. Используйте его, когда доверяете задаче и не хотите отвлекаться.

## Переключение режимов

- **Для одной сессии:** нажмите кнопку-щит в композиторе. Каждое нажатие переключает на следующий режим.
- **Для новых сессий:** выберите значение по умолчанию в **Настройки → Сессии → Разрешения**. У существующих сессий режим сохраняется.

Суб-агенты следуют за сессией, которая их запустила.

## Страховочная сетка

В этом режиме OpenChamber спрашивает [Jev](/ru/classification-providers/) о каждом запросе: рутинный ли он или решать вам? Чтение, сборка, запуск тестов, редактирование файлов проекта и обычные коммиты проходят. Переписывание истории git, удаление данных, изменение системы, деплой, публикация где-то или отправка файлов наружу ждут вас, как и всё неясное.

Удержанный запрос показывает обычную карточку разрешения с одной лишней строкой **Страховочная сетка удержала это действие для вашего решения** и видом действия. Если Jev не может ответить за четыре секунды, действие тоже ждёт вас. Страховочная сетка никогда не разрешает что-то из-за сбоя проверки.

Страховочной сетке нужен [провайдер классификации](/ru/classification-providers/). Без него кнопка-щит её пропускает, а в Настройках она отключена.

## Продолжает работать, пока вас нет

Режим живёт в сервере OpenChamber, поэтому продолжает отвечать на запросы после закрытия вкладки или блокировки телефона и переживает перезапуски.

> В VS Code страховочной сетки нет. Расширение предлагает спрашивать каждый раз и принимать всё, а на запросы отвечает, только пока открыта панель OpenChamber.

## Связанное

- [Разрешения в документации OpenCode](https://opencode.ai/v2/docs/permissions/): напишите собственные правила разрешить, спросить и запретить
- [Провайдеры классификации (Jev)](/ru/classification-providers/): настройте модель за страховочной сеткой
- [Уведомления](/ru/notifications/): узнайте о ждущем запросе
