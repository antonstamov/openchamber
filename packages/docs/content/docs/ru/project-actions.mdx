# Действия проекта

Действие проекта — shell-команда, которую вы сохраняете один раз и запускаете кликом: ваш dev-сервер, сборка, прогон тестов. У каждого проекта собственный список. Настройте их в **Настройки → Проекты → Действия проекта**.

## Добавление действия

1. Откройте **Настройки → Проекты** и найдите раздел **Действия проекта**.
2. Добавьте действие, дайте ему имя, выберите значок и введите команду для запуска.
3. Сохраните.

Действие можно ограничить определёнными операционными системами, если команда имеет смысл только на одной.

## Запуск действия

В разделе **Проект** панели рабочего статуса, карточке справа от чата, есть строка действий. Нажмите действие, чтобы запустить, и нажмите снова, чтобы остановить. Шеврон рядом выбирает другое действие, а его пункт **Добавить новое действие** открывает **Настройки → Проекты**. Строка показывает последнее выбранное действие, а пока действие выполняется — показывает его. Когда у запуска есть адрес превью, кнопка-глобус рядом со строкой открывает его.

С клавиатуры нажмите **⌘⌥R** на macOS или **Ctrl+Alt+R** в Windows и Linux, чтобы открыть диалог действий проекта. В нём перечислены действия текущего проекта с их состоянием. Стрелки двигают подсветку, Enter запускает простаивающее действие или останавливает выполняющееся, Esc закрывает диалог. Поле поиска фильтрует список, а **Настроить действия** в конце открывает настройки действий проекта. Диалог открывается с подсвеченным действием из рабочего статуса, поэтому шорткат и затем Enter повторяют ваш последний запуск. Чтобы сменить шорткат, найдите **Открыть действия проекта** в **Настройки → Горячие клавиши**.

В палитре команд, открытой через ⌘P или Ctrl+P, введите «run» или имя действия, чтобы найти записи вроде **Run: dev** и **Stop: dev**. **Действия проекта** в палитре открывает диалог.

Каждое действие выполняется в терминале в папке сессии — worktree, если сессия в нём, или основном checkout для действий, настроенных запускаться там. Терминал открывается, чтобы было видно вывод. Действия проекта доступны на десктопе и в веб-приложении. В VS Code, на телефонах и в сессиях под Чатами их нет.

## Авто-открытие dev-сервера

Включите **авто-открытие URL** для действия, запускающего сервер. OpenChamber следит за выводом в поиске локального адреса и предлагает открыть его — см. [Превью и dev-серверы](/ru/preview/). На десктопе его также можно пустить через проброс SSH-порта.

Если у сервера фиксированный адрес, укажите его в поле URL действия. `{worktree}` и `{branch}` подставляют checkout, в котором выполняется действие, поэтому одно действие работает в каждом worktree. С [portless](https://github.com/vercel-labs/portless) адрес `https://{worktree}.myapp.localhost` открывает `https://auth.myapp.localhost` в worktree на `feature/auth` и `https://myapp.localhost` в основном checkout. Поле может вообще не понадобиться: когда portless печатает свой адрес, OpenChamber открывает его вместо порта за ним. На десктопе, подключённом к удалённому инстансу, открывается порт, так как через туннель к удалённой машине проходят только loopback-порты.
