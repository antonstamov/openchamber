# Переменные окружения

OpenChamber читает эти переменные окружения при запуске. Для служб автозапуска `openchamber startup enable` по умолчанию снимает слепок текущего окружения, поэтому перезапустите её после изменения переменных, которые должна использовать служба. Переменные, которые OpenChamber сам задал в оболочке, из которой вы его запускаете, — например в терминале приложения для компьютеров или в оболочке агента, — в службу не попадают; ваши собственные экспорты оттуда тоже переносятся, если только вы не переэкспортируете имя, которое OpenChamber уже задал в этой оболочке, чего обычный терминал избегает.

## Переменные для OpenCode, Git и терминала

Чтобы дать OpenCode, Git, терминалу и [действиям проекта](/ru/project-actions/) собственные переменные, например токен API или адрес базы данных, добавьте их в **Настройки → Общие → Переменные окружения**, вместо того чтобы экспортировать их перед запуском OpenChamber. Значения остаются на машине, где работает OpenChamber, в `environment.json` в каталоге данных, читаемом только вашим пользователем. Настройки больше никогда не показывают значение: его можно заменить или удалить, но не прочитать обратно.

- OpenCode получает их при запуске, поэтому перезапустите его после изменения. В настройках есть кнопка.
- Переменные, заданные через `opencode service set env`, тоже доходят до OpenCode. Побеждают те, что из настроек.
- Git, терминал и действия проекта получают их при следующем запуске.
- Переменные, которые OpenChamber задаёт для самого OpenCode, например его пароль и конфигурация, побеждают ваши.

Проект может добавить собственные переменные или команду вроде `direnv export json`, которая их выводит, в **Настройки → Проекты**. См. [Проекты](/ru/projects/#окружение-проекта).

Переменные не доходят до сервера OpenCode, который вы запустили сами, а в расширении VS Code такой настройки нет. Всё ниже читает сам OpenChamber при запуске.

## Сервер OpenChamber

### `OPENCHAMBER_HOST`

Адрес привязки веб-сервера OpenChamber. Используйте `0.0.0.0`, чтобы разрешить доступ с других машин.

### `OPENCHAMBER_LAN_URL`

Адрес, по которому другие устройства в вашей сети обращаются к OpenChamber, например `http://192.168.1.20:3000`. Ссылки подключения и QR-коды предлагают его вместо адреса, который определяет сам OpenChamber. Задайте его, когда это предположение неверно, например в Docker, где OpenChamber видит только внутренний адрес контейнера.

### `OPENCHAMBER_UI_PASSWORD`

Пароль для интерфейса в браузере. Используйте его при привязке за пределами localhost, при использовании туннелей или работе за обратным прокси.

### `OPENCHAMBER_UI_SESSION_TTL_HOURS`

Сколько часов длится вход в браузере, когда «доверять этому устройству» выключено. По умолчанию `12`.

### `OPENCHAMBER_UI_TRUSTED_SESSION_TTL_DAYS`

Сколько дней длится вход на устройстве, которое вы решили считать доверенным. По умолчанию `7`.

### `OPENCHAMBER_API_ONLY`

Запускает OpenChamber в headless-режиме при значении `true` или `1`. Маршруты API остаются доступны для клиентов на компьютерах и мобильных устройствах, но интерфейс браузера не обслуживается.

### `OPENCHAMBER_FRAME_ANCESTORS`

Источники, которым разрешено показывать OpenChamber во фрейме на своей странице, через пробел, например `https://dash.example.com`. `*` разрешает любой сайт. По умолчанию встраивать его могут только сам OpenChamber и его приложения для компьютеров и мобильных устройств — это не даёт другим сайтам перекрывать его кнопки.

### `OPENCHAMBER_DATA_DIR`

Переопределяет каталог данных OpenChamber. По умолчанию `~/.config/openchamber`.

Всё, что хранит OpenChamber, живёт в этом каталоге: настройки, аутентификация, конфигурации проектов, темы, планы и речевые модели. Инстанс, использовавший собственный каталог до версии 1.23, при первом запуске копирует оттуда папки `projects`, `themes` и `speech-models` из `~/.config/openchamber`; оригиналы остаются на месте, слияния не происходит.

### `OPENCHAMBER_CHATS_DIR`

Перемещает управляемые каталоги чатов, которые OpenChamber создаёт для чатов без проекта. По умолчанию `~/.config/openchamber/chats`. Задайте каталог, читаемый сервером OpenCode, когда OpenChamber и OpenCode работают от разных пользователей. Существующие чаты не перемещаются.

### `OPENCHAMBER_COMPRESS_API`

Управляет сжатием ответов API. Используйте `true` или `1`, чтобы принудительно включить, `false` или `0` — чтобы выключить.

### `OPENCHAMBER_SKIP_API_COMPRESSION`

Отключает сжатие ответов API при значении `true` или `1`. Имеет приоритет над `OPENCHAMBER_COMPRESS_API`.

### `OPENCHAMBER_VERBOSE_REQUEST_LOGS`

Включает подробные журналы HTTP-запросов при значении `true` или `1`.

### `OPENCHAMBER_UPDATE_API_URL`

Переопределяет эндпоинт API проверки обновлений. Большинству пользователей лучше оставить незаданным.

### `OPENCHAMBER_PACKAGE_MANAGER`

Принудительно задаёт менеджер пакетов для операций обновления, когда автовыбор неверен.

## Прокси

### `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`

Отправляет собственные исходящие запросы OpenChamber, такие как лимиты использования и каталоги навыков, через прокси. Строчные имена тоже работают. Хосты из `NO_PROXY` подключаются напрямую, и `localhost`, `127.0.0.1` и `::1` — всегда, поэтому обратные вызовы входа и локальный сервер OpenCode продолжают работать.

## Сервер OpenCode

### `OPENCODE_HOST`

Подключает OpenChamber к существующему серверу OpenCode. Значение должно быть источником `http` или `https` с явным портом и без пути, запроса и хеша. `OPENCODE_HOST` имеет приоритет над `OPENCODE_PORT`.

### `OPENCODE_PORT`

Задаёт порт сервера OpenCode. С управляемым OpenCode запрашивает управляемый порт; с `OPENCODE_SKIP_START=true` подключается к внешнему серверу на этом порту.

### `OPENCODE_SKIP_START`

Не даёт OpenChamber запускать собственный сервер OpenCode при значении `true`.

### `OPENCHAMBER_OPENCODE_HOSTNAME`

Имя хоста привязки для сервера OpenCode, управляемого OpenChamber. По умолчанию `127.0.0.1`.

### `OPENCHAMBER_OPENCODE_HEALTH_TIMEOUT_MS`

Лимит времени проверки работоспособности OpenCode в миллисекундах. По умолчанию `5000`.

### `OPENCHAMBER_OPENCODE_HEALTH_CONSECUTIVE_FAILURES`

Подряд идущие засчитанные сбои проверок работоспособности, после которых OpenChamber перезапускает всё ещё работающий управляемый процесс OpenCode. По умолчанию `20`. Занятые сессии могут отложить перезапуск.

### `OPENCHAMBER_OPENCODE_HEALTH_INTERVAL_MS`

Переопределяет интервал проверки работоспособности управляемого OpenCode в миллисекундах. Также задаёт минимальное время между засчитанными сбоями. По умолчанию `0`, что сохраняет серверный интервал `15000` миллисекунд.

### `OPENCHAMBER_OPENCODE_HEALTH_CACHE_MS`

Сколько OpenChamber повторно использует результат проверки работоспособности управляемого OpenCode, включая сбой, в миллисекундах. По умолчанию `750`.

### `OPENCODE_BINARY`

Путь к исполняемому файлу `opencode`, который должен запускать OpenChamber.

### `OPENCODE_CONFIG`

Путь к конкретному файлу конфигурации OpenCode.

### `OPENCODE_CONFIG_DIR`

Путь к конкретному каталогу конфигурации OpenCode для агентов, навыков, сниппетов и обнаружения конфигурации.

### `OPENCODE_DATA_DIR`

Собственный каталог данных для управляемого сервера OpenCode.

### `OPENCODE_JWT_SECRET`

Секрет для подписи токенов аутентификации интерфейса. Используйте длинное случайное значение для постоянных развёртываний служб.

## Терминал и Git

### `OPENCHAMBER_TERMINAL_SHELL`

Исполняемый файл оболочки для терминальных сессий OpenChamber.

### `OPENCHAMBER_GIT_BINARY`

Исполняемый файл Git для функций Git в OpenChamber.

### `GIT_BINARY`

Альтернативное переопределение исполняемого файла Git. Для специфичной OpenChamber конфигурации предпочитайте `OPENCHAMBER_GIT_BINARY`.

### `OPENCHAMBER_GIT_READ_CACHE_TTL_MS`

Время жизни кеша Git-чтений файлов в миллисекундах. Задайте `0`, чтобы отключить этот кеш при отладке.

## Голос и туннели

### `OPENAI_API_KEY`

Ключ API, который голосовые функции OpenChamber используют при обращении к самому OpenAI. Он никогда не отправляется на собственный OpenAI-совместимый сервер: дайте тому серверу собственный ключ в настройках.

### `OPENCHAMBER_ALLOW_REMOTE_OPENAI_COMPAT_URLS`

Разрешает удалённые OpenAI-совместимые базовые URL для голосовых функций при значении `true` или `1`.

### `NGROK_AUTHTOKEN`

Токен аутентификации ngrok для туннельных команд OpenChamber. Ngrok можно также настроить командой `ngrok config add-authtoken <token>`.

## Вспомогательные средства выполнения

### `BUN_BINARY`

Исполняемый файл Bun, который OpenChamber должен использовать при порождении фоновых процессов.

### `BUN_INSTALL`

Корень установки Bun. OpenChamber использует его, чтобы находить `bin/bun` для запуска фоновых служб и обновлений.

### `VITE_OPENCODE_URL`

Базовый URL API времени сборки для веб-приложения, собранного Vite. Большинству пользователей не следует задавать его при обычном использовании CLI или приложения для компьютеров.
