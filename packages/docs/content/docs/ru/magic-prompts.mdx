# Магические промпты

OpenChamber использует встроенные промпты за кулисами, когда делает что-то автоматически — пишет сообщение коммита, черновик PR, ревью issue, разрешает конфликт, подводит итог сессии. Магические промпты — место, где вы читаете и переписываете эти промпты. Откройте их в **Настройки → Магические промпты**.

Для обычного использования эта страница не нужна. Открывайте её, когда хотите, чтобы сценарий вёл себя иначе — например, сообщения коммитов в определённом стиле.

## Редактирование промпта

1. Откройте **Настройки → Магические промпты**.
2. Выберите промпт из групп в боковой панели — Git, Планирование и Сессия.
3. Отредактируйте текст и сохраните.

У некоторых промптов есть видимая часть (сообщение, которое вы бы увидели) и часть с инструкциями (скрытые указания для агента). Промпты могут содержать `{{плейсхолдеры}}`, которые подставляет OpenChamber, например дифф или заголовок issue — оставляйте их на месте.

## Сброс

Передумали? У каждого промпта есть **сбросить к умолчанию**, а также общий **сбросить всё**, если хотите начать заново везде.

## Промпты проекта

У промпта также может быть переопределение для одного проекта. OpenChamber использует переопределение проекта, если оно есть, иначе ваше глобальное переопределение, иначе встроенный текст. Сохранённое переопределение учитывается, даже если оно пустое.

Чтобы добавить его, выберите проект в селекторе вверху боковой панели, затем выберите **Проект** в разделе **Область**. Нажмите **Сохранить** под каждым изменённым блоком. Кнопки сброса меняют только открытую область. В **Проекте** пункты **Удалить переопределение проекта** и **Удалить все переопределения проекта** возвращают ваше глобальное переопределение или встроенный текст. Сохранение встроенного текста в **Глобальной** области удаляет ваше глобальное переопределение. В **Проекте** этот текст остаётся сохранённым, поэтому проект сохраняет встроенный текст, даже если ваше глобальное переопределение говорит другое.

Переопределения проекта сохраняются в ключе `magicPrompts` файла `.openchamber/project.json` в checkout проекта, том же файле, что и [конфигурация репозитория](/ru/repository-config/). Закоммитьте его, чтобы поделиться промптами с командой. Глобальные переопределения остаются в `magic-prompts.json` в папке данных сервера.

Worktree использует промпты проекта из его основного checkout, если только вы не добавили worktree как отдельный проект. Чат без проекта, папка, не принадлежащая ни одному проекту, и работа в изолированном пространстве используют только глобальные промпты. В расширении VS Code страницы Магических промптов нет. Там редактируйте файлы вручную, а глобальный файл — всегда `~/.config/openchamber/magic-prompts.json`.

Когда файл проекта нельзя прочитать, например из-за невалидного JSON, сценарии, которым он нужен, останавливаются с ошибкой и не откатываются на встроенный текст. Настройки показывают причину и кнопку **Повторить**. Отсутствующий файл проекта — не ошибка, и тогда проект наследует каждый промпт.

## Где используется каждый промпт

Под каждым промптом ниже указано, где он выполняется и какой триггер его запускает. Проверьте триггер перед редактированием, чтобы знать, какой сценарий вы меняете.

### Git

| Промпт | Где выполняется | Когда срабатывает |
| --- | --- | --- |
| Генерация коммита | Кнопка генерации в поле коммита в виде git и экран Изменений на мобильном | Вы генерируете сообщение коммита. Подставляются выбранные файлы и недавние темы коммитов ветки, чтобы тема совпадала с существующим стилем репозитория. |
| Генерация PR | Форма создания pull request во вкладке PR вида git | Вы генерируете заголовок и тело PR. Подставляются базовая и головная ветки, коммиты и изменённые файлы между ними, ваш дополнительный контекст и шаблон PR репозитория, если он есть. |
| Обзор | Панель обзора Изменений | Вы генерируете обзор. По умолчанию пусто. Всё, что вы напишете, добавляется к промпту обзора как ваши предпочтения по тону, акцентам и глубине; формат обзора изменить нельзя. |
| Разрешение конфликтов слияния/ребейза | Диалог конфликтов в виде git, когда слияние или ребейз останавливается на конфликтах | Вы выбираете «Разрешить в текущей сессии» или «Разрешить в новой сессии». Агент читает конфликтующие файлы, предлагает стратегию разрешения для каждого файла и ждёт вашего подтверждения перед редактированием, стейджингом или продолжением операции. |
| Разрешение конфликтов cherry-pick | Раздел «Перенос коммитов» для сессии worktree | Перенос коммитов сессии на целевую ветку упирается в конфликт, и вы передаёте его агенту. Агент разрешает внутри временного worktree, стейджит разрешённые файлы и продолжает cherry-pick. |

### Планирование

| Промпт | Где выполняется | Когда срабатывает |
| --- | --- | --- |
| Планирование todo | Панель Todos в боковой панели проекта | Вы отправляете todo в сессию или в новую сессию worktree. Текст todo становится видимым сообщением; инструкции превращают его в диалог планирования с вопросами вместо прыжка сразу к реализации. |
| Улучшить план | Действие «Улучшить» на сохранённом плане в виде Планов | Вы отправляете сохранённый план в сценарий улучшения. Агент сначала читает файл плана, затем предлагает изменения, основанные на текущем состоянии репозитория, и предлагает отредактировать тот же файл. |
| Выполнить план | Действие «Выполнить» на сохранённом плане | Вы отправляете сохранённый план в сценарий выполнения. Агент читает файл плана и выполняет его целиком без расширения области, сохраняя правки плана обратно в файл, если сам план оказался неверным. |

### Сессия

Большинство из них лежат за слэш-командами в композиторе. Большинство также показаны как стартовые чипы в черновике новой сессии.

| Промпт | Где выполняется | Когда срабатывает |
| --- | --- | --- |
| Тур по кодовой базе | `/explore` | Вы просите высокоуровневую ориентацию по кодовой базе. |
| Итог сессии | `/summary`, опционально `/summary <topic>` | Вы подводите итог разговора, полезно для передачи в новую сессию. Нужна существующая сессия. |
| Ревью рабочей области | `/workspace-review` | Вы просите агента проверить текущий дифф рабочей области на замысел, корректность и безопасность. |
| Планирование фичи | `/plan-feature` | Вы превращаете грубую идею фичи в план реализации через направляемый диалог с вопросами и ответами. |
| Создание цели | `/craft-goal`, опционально `/craft-goal <idea>` | Вы превращаете идею в проверяемую цель для диалога целей. |
| Наверстать | `/catch-up` | Вы возвращаетесь в проект и спрашиваете, как дела и за что взяться дальше. |
| Отладка | `/debug` | Вы расследуете баг: агент выдвигает гипотезы, подтверждает корневую причину по коду и только затем предлагает исправление. |
| Взвесить варианты | `/weigh` | Вы знаете, что хотите построить, но не как. Агент сравнивает два-три подхода и рекомендует один. |
| Слияние | Действие «Запустить слияние» на группе мульти-запуска | Вы объединяете выводы нескольких запусков в один ответ. Выводы запусков дописываются после инструкций. |

### Промпты без записи в Настройках

Несколько промптов срабатывают автоматически и не имеют редактируемой страницы в Настройках:

| Промпт | Когда срабатывает |
| --- | --- |
| Запланированная задача | `/schedule-task`, опционально с начальной идеей. Ведёт диалог, определяющий запланированную задачу. |
| Передача на ревью | `/handoff-review` или кнопка Ревью в виде диффа с включённой передачей. Генерирует передачу в рабочей сессии. |
| Стартовое сообщение сессии ревью | Открывающее сообщение сгенерированной сессии ревью, с передачей, если она была создана, и без неё в противном случае. |
| Ответ обратной связи ревью / реализации | Челночные сообщения между двумя сессиями: обратная связь ревьюера уходит обратно в сессию реализации, а ответ исполнителя возвращается в сессию ревью. |
