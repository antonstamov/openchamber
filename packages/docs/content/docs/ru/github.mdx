# Git-хосты: задачи и запросы на слияние

Подключите учётную запись на хосте, где живёт ваш проект, и OpenChamber сможет перечислять его задачи и запросы на слияние, начинать с них сессию, а также открывать, рецензировать и сливать запросы на слияние за вас. Встроены пять хостов: GitHub, включая GitHub Enterprise; GitLab, включая самостоятельно управляемый GitLab; Gitea; Forgejo, включая Codeberg; и Gerrit. [Расширение](/ru/extensions/#расширение-как-git-хост) может добавить ещё один.

Remote проекта решает, с каким хостом говорит OpenChamber. Проект, чей `origin` находится на gitlab.com, использует вашу учётную запись GitLab для доски, значка запроса на слияние на его ветках и панели Git. Remote на псевдониме хоста из `~/.ssh/config`, например `github.com-work`, не сопоставляется ни с каким хостом. Gitea и Forgejo сопоставляют псевдоним, чья SSH-конфигурация указывает на веб-адрес инстанса, и remote на SSH-адресе клонирования инстанса, если вы введёте этот адрес в **Настройки → Интеграции**.

Слова следуют за хостом. GitLab говорит «запрос на слияние», а Gerrit — «изменение».

## Подключение хоста

1. Откройте **Настройки → Интеграции**. У каждого хоста своя карточка.
2. Разверните карточку хоста вашего проекта и войдите:
   - **GitHub**: выберите **Подключить GitHub**, откройте показанную ссылку, введите короткий код и подтвердите. Для GitHub Enterprise выберите **Добавить инстанс** под **Другие инстансы**, введите адрес вашего сервера и вставьте персональный токен доступа.
   - **GitLab**: на gitlab.com войдите с коротким кодом, персональным токеном доступа или входом `glab`. Для самостоятельно управляемого GitLab добавьте его адрес и вставьте персональный токен доступа.
   - **Gitea**: добавьте адрес вашего сервера и вставьте персональный токен доступа.
   - **Forgejo**: для Codeberg вставьте персональный токен доступа; для другого сервера сначала добавьте его адрес.
   - **Gerrit**: добавьте адрес вашего сервера, затем имя пользователя Gerrit и HTTP-пароль.

После подключения ваша учётная запись показывается на карточке. Можно подключить больше одной учётной записи на хосте и переключаться между ними или отключиться в любой момент. Если CLI `gh` вошёл на той же машине, OpenChamber тоже может использовать его для GitHub. Области, нужные каждому токену, и нужные версии каждого хоста — в [Интеграциях](/ru/integrations/#gitlab-gitea-forgejo-и-gerrit).

Подключённая учётная запись может также быть [Git-идентичностью](/ru/git-identities/) проекта, чтобы коммиты несли её имя, а отправки по HTTPS использовали её токен.

## Начало работы из задачи или запроса на слияние

Создавая [сессию в worktree](/ru/worktrees/), её можно начать из задачи или запроса на слияние хоста проекта:

- выберите **задачу**, и OpenChamber назовёт ветку в её честь
- выберите **запрос на слияние**, и он извлечёт ветку запроса на слияние; можно включить его diff, чтобы у агента было всё изменение
- выберите **изменение Gerrit**, и он извлечёт последний набор патчей в ветку с именем `change-<number>`

Новая сессия открывается с элементом, уже прикреплённым к полю сообщения. Ничего не отправляется за вас: выберите модель и агента, скажите, что нужно сделать, и отправьте.

Доска [Задачи и PR](/ru/issues-and-prs/) перечисляет те же элементы с фильтрами, предпросмотром, комментариями и рецензиями, и тоже запускает оттуда сессии.

## Открытие и ведение запросов на слияние

На вкладке **PR** в [панели Git](/ru/git/) можно создать запрос на слияние, обновить его, отметить черновик готовым или слить его. OpenChamber может написать заголовок и описание из ваших изменений.

- **GitLab**: та же вкладка открывает запросы на слияние. Слияние предлагает merge и squash.
- **Gitea** и **Forgejo**: так же, как на GitHub.
- **Gerrit**: изменение создаётся отправкой на ревью, и каждая следующая отправка загружает новый набор патчей. См. [Отправка на ревью в Gerrit](/ru/git/#отправка-на-ревью-в-gerrit). Слияние — это **Отправить**, и оно ждёт, пока изменение выполнит свои требования к отправке. Рецензии — это голоса на метках проекта, например Code-Review и Verified.

## Привязка задачи или запроса на слияние к сообщению

В редакторе чата откройте меню **+** и выберите запись ссылки для вашего хоста, например **Связать задачу или PR GitHub**, **Связать задачу или MR GitLab** или **Связать изменение Gerrit**. Выберите один или несколько элементов. Каждый пойдёт со следующим сообщением как контекст, запрос на слияние может принести свой diff, а панель статуса работы сессии сохраняет ссылку на него. Прикрепление лишь добавляет контекст; ваше сообщение говорит, что с ним делать.

В Gerrit нет задач, поэтому там показываются только изменения.
