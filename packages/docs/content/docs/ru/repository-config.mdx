# Конфигурация репозитория

Действия проекта, команды настройки worktree и стартеры черновиков по умолчанию живут в ваших личных настройках OpenChamber. Никто другой их не видит. Если хотите, чтобы коллега, клонировавший репозиторий, получил то же действие dev-сервера и тот же `bun install` в каждом новом worktree, переместите эти элементы в репозиторий.

OpenChamber хранит их в `.openchamber/project.json` в корне репозитория. Файл появляется только при перемещении первого элемента туда и исчезает, когда вы перемещаете последний обратно. Коммитьте его как обычный файл.

## Что где хранится

| Остаётся в ваших настройках | Можно переместить в репозиторий |
|---|---|
| Notes и todos | Project actions |
| Scheduled tasks | Worktree setup commands |
| Какое действие репозитория скрыто для вас | Draft starters (pinned commands и skills) |
| Ваш ответ о доверии командам репозитория | Plans |

Заметки, todos и запланированные задачи — ваши. В репозиторий они никогда не попадают.

## Перемещение элемента

Откройте **Настройки → Проекты** и выберите проект. У каждого действия и каждой команды настройки есть кнопка **Move to repository**, а у каждого элемента из репозитория — **Move to my settings**. Стартеры на экране новой сессии показывают ту же пару при наведении. У планов она есть в каждой строке вкладки Plans.

Перемещение — это просто перемещение. Элемент уходит из одного места и попадает в другое, поэтому дублирования нет.

Элементы из репозитория помечены бейджем **In repo**. Действия репозитория можно также скрыть из своего меню кнопкой **Hide for me**. Это меняет только ваше меню, а не файл.

## Файл

```json
{
  "version": 1,
  "setupWorktree": [
    "bun install"
  ],
  "setupWorktreeWait": true,
  "teardownWorktree": [
    "docker compose down"
  ],
  "projectActions": [
    {
      "id": "dev",
      "name": "Dev server",
      "command": "bun run dev",
      "icon": "rocket",
      "autoOpenUrl": true,
      "platforms": ["macos", "linux"]
    },
    {
      "id": "test",
      "name": "Tests",
      "command": "bun test"
    }
  ],
  "draftStarters": [
    { "type": "skill", "name": "triage-prs" }
  ],
  "plansDir": "docs/plans"
}
```

Обязателен только `version`. Все остальные ключи необязательны, и OpenChamber записывает только те, в которых что-то есть.

`setupWorktree` — список shell-команд, которые OpenChamber выполняет внутри нового worktree сразу после создания, по порядку. Путь основного чекаута — через `$ROOT_PROJECT_PATH`. `setupWorktreeWait: true` заставляет OpenChamber дождаться этих команд, прежде чем запускать сессию в worktree.

`teardownWorktree` — список shell-команд, которые OpenChamber выполняет внутри worktree прямо перед его удалением или архивацией, по порядку, например `docker compose down` для стека, запущенного worktree. Если одна из них не удалась, worktree остаётся, и OpenChamber показывает ошибку команды. Команды удаления из репозитория выполняются первыми, затем ваши собственные, в том числе когда вы используете только свои команды настройки. К ним применяется тот же вопрос о доверии, что и к командам настройки.

`projectActions` — список действий проекта, тех, что запускаются из Work Status, диалога действий проекта и палитры команд. `id`, `name` и `command` обязательны. `icon` необязателен и по умолчанию заменяется значком запуска; известные OpenChamber имена: `play`, `build`, `lint`, `terminal`, `tools`, `bug`, `flask`, `rocket`, `code`, `server`, `branch`, `search`, `settings`, `brain`, `stack`, `robot`, `command` и `file`. `autoOpenUrl: true` открывает адрес, который выводит команда, см. [Preview & Dev Servers](/ru/preview/). `platforms` ограничивает действие значениями `macos`, `linux` или `windows`. `runIn: "parent"` запускает действие в основном чекауте вместо текущего worktree.

`draftStarters` закрепляет команды и навыки на экране новой сессии. Каждая запись — `{ "type": "command" | "skill", "name": "..." }`, а сами команда или навык должны существовать в конфиге OpenCode репозитория.

`plansDir` — где живут планы репозитория. Если не указан, используется `.openchamber/plans`. См. ниже.

Этот файл можно писать вручную. Ключ неверной формы делает недействительным весь файл, и страница Projects скажет вам почему, вместо того чтобы молча его игнорировать.

## Как объединяются элементы репозитория и личные

Команды настройки из репозитория выполняются первыми, затем ваши собственные. Отметьте **Use only my setup commands** в разделе Worktree, чтобы полностью пропустить команды репозитория.

Действия объединяются по `id`. Действие в ваших настройках с тем же id, что у действия репозитория, заменяет его. Стартеры объединяются по имени.

Флаг ожидания берётся из ваших настроек, если вы его задали, иначе — из репозитория.

## Доверие

Команды настройки и действия из репозитория выполняются на вашей машине, а `git pull` может их изменить. Поэтому перед первым запуском одной из них OpenChamber показывает точные команды и спрашивает. **Trust and run** запоминает ваш ответ на этом инстансе. **Not this time** выполняет только ваши собственные команды.

Ответ привязан к самим командам. Когда pull меняет команду репозитория, вопрос возвращается для нового текста. Забыть ответ можно кнопкой **reset trust** в разделе Worktree настроек проекта.

Перемещение собственной команды в репозиторий считается доверием ей, поскольку вы её только что видели.

## Планы в репозитории

Планы на вкладке Plans тоже могут жить в репозитории в виде Markdown-файлов. Папка по умолчанию — `.openchamber/plans`. Задайте **Plans folder** в настройках проекта, чтобы использовать другую папку внутри репозитория, например `docs/plans`, если команда уже хранит планы там. Пользовательская папка полностью заменяет стандартную: OpenChamber читает и пишет только в неё, поэтому при смене перенесите существующие файлы сами.

Каждый `.md`-файл в этой папке показывается на вкладке Plans, включая файлы, записанные другими инструментами. Редактирование в OpenChamber сохраняет файл как вы его ввели. План, перемещённый в репозиторий, сохраняет свою идентичность, поэтому сессии, к которым он был прикреплён, всё ещё его находят.
