# Сервер OpenCode

OpenChamber работает поверх сервера OpenCode. По умолчанию он запускает его за вас, поэтому делать ничего не нужно. Эта страница нужна, только если вы хотите указать OpenChamber на уже запущенный сервер или управлять тем, который он запускает.

## Как OpenChamber находит сервер

При запуске OpenChamber ищет сервер в таком порядке:

1. переиспользовать уже запущенный им сервер
2. подключиться к внешнему, если вы так указали (см. ниже)
3. автоматически найти сервер на порту по умолчанию (`4096`)
4. иначе запустить и управлять собственным

Если ничего не настроено, автоматически происходит шаг 4, и всё работает.

## Подключение к уже запущенному серверу

Задайте это перед запуском OpenChamber:

```bash
OPENCODE_HOST=http://localhost:4096 OPENCODE_SKIP_START=true openchamber
```

- `OPENCODE_HOST` — полный адрес вашего сервера OpenCode, включая порт (значение вроде `http://localhost:4096`). В конце не должно быть пути.
- `OPENCODE_SKIP_START=true` — говорит OpenChamber не запускать собственный сервер.

Если нужно поменять только порт, задайте `OPENCODE_PORT` вместо `OPENCODE_HOST`.

Если у `OPENCODE_HOST` нет порта или есть путь, OpenChamber игнорирует его и возвращается к запуску собственного сервера. Следите за предупреждением `[config]` в логах запуска, если ожидаемое подключение не произошло.

## Управление сервером из CLI

```bash
openchamber status
openchamber logs
openchamber restart
openchamber stop
```

Сам по себе `openchamber` запускает сервер в фоне. Добавьте `--foreground`, чтобы оставить его привязанным к терминалу.

## Запуск OpenChamber при входе

Используйте `startup enable`, чтобы установить нативный пользовательский сервис. OpenChamber использует `launchd` на macOS, `systemd --user` на Linux и планировщик задач в Windows.

```bash
openchamber startup enable
openchamber startup status
openchamber startup disable
```

Чтобы защитить интерфейс, задайте пароль при включении сервиса:

```bash
OPENCHAMBER_UI_PASSWORD='secret' openchamber startup enable
```

Для headless-сервера, который стартует при входе и предназначен для десктопных или мобильных клиентов, добавьте `--api-only` и доступный хост:

```bash
openchamber startup enable --port 3000 --api-only --host 0.0.0.0 --ui-password secret
```

`startup enable` сохраняет снимок текущего окружения в сервис, чтобы он вёл себя ближе к запуску `openchamber` из той же оболочки. Так сохраняются токены провайдеров, `PATH`, настройки SSH-агента и другие переменные авторизации/конфигурации CLI. Переменные, которые запущенный OpenChamber поместил в эту оболочку, например собственные настройки десктопного приложения или пароль управляемого OpenCode, исключаются. Используйте `--no-env-snapshot`, если хотите минимальное окружение сервиса.

Служба автозапуска запоминает `--port`, `--host`, `--ui-password` и `--api-only`. Перезапуск и обновление через CLI повторно используют эти сохранённые настройки.

Чтобы создать ссылку подключения для другого приложения OpenChamber, используйте:

```bash
openchamber connect-url --port 3000 --server http://your-host:3000 --qr
```

Запустите `openchamber connect-url --help`, чтобы увидеть все опции ссылок, включая `--name`, `--lan`, `--server`, `--api-only`, `--ui-password` и `--qr`.

Туннелями для этого работающего сервиса можно по-прежнему управлять отдельно:

```bash
openchamber tunnel start --port 3000
openchamber tunnel stop --port 3000
```

Остановка туннеля не перезапускает сервис или приложение.

## «OpenCode перезапускается»

Пока сервер запускается или перезапускается, OpenChamber показывает состояние «OpenCode перезапускается» и приостанавливает запросы до готовности. Это нормально сразу после запуска или перезапуска. Если оно не исчезает, см. [подключение OpenCode](/ru/troubleshooting/opencode-connection/).
