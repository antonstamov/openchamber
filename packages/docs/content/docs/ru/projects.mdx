# Проекты

Проект — это папка на вашем компьютере, которую отслеживает OpenChamber, обычно один репозиторий с кодом. Переключение проектов меняет папку, в которой работает агент, а также сессии и настройки этого проекта.

## Добавление проекта

Добавить проект можно несколькими способами:

- пункт **Add project** в палитре команд
- кнопка **+** вверху боковой панели сессий
- обозреватель папок при выборе каталога

Укажите папку, и OpenChamber запомнит её. Название берётся из папки; позже его можно изменить.

## Переключение проектов

Выберите проект в боковой панели, чтобы сделать его активным. Всё — сессии, git, заметки — следует за открытым проектом.

## Как сделать проект узнаваемым

Откройте **Настройки → Проекты**, чтобы задать проекту собственное имя, цвет или значок. OpenChamber пытается подобрать значок автоматически — см. [Project icons](/ru/project-icons/).

> В VS Code OpenChamber всегда использует открытую папку как единственный проект, поэтому добавлять или переключать нечего. Страница настроек Projects там скрыта.

## Группировка сессий по папкам

В боковой панели щёлкните сессию правой кнопкой мыши и выберите **Move to folder**, чтобы положить её в папку, или **New folder...**, чтобы создать её. Папка принадлежит корню проекта или одному worktree, а в строке папки есть кнопки переименования и удаления. Папка корня проекта может также содержать целые worktree: откройте меню worktree и выберите **Move to folder**. Удаление папки сохраняет её содержимое; оно возвращается в проект.

Папки хранятся на сервере OpenChamber, поэтому всё, что подключено к одному серверу, показывает одни и те же папки: другой компьютер, вошедший в него, веб-приложение и телефон. Изменение на одном устройстве появляется на остальных в течение секунды, без перезагрузки. У каждого сервера свои папки. Какие папки свёрнуты, хранится на каждом устройстве.

Телефон показывает папки, включая worktree в них, но не может их менять. Перемещайте сессии на десктопе или в веб-приложении.

Когда устройство впервые подключается после обновления с версии, хранившей папки на каждом устройстве, его папки добавляются к серверным. Папка с тем же именем в том же месте, что уже есть на сервере, объединяется с ней, и её сессии переходят туда; ничего не теряется. Сессия, уже разложенная сервером, остаётся в серверной папке.

Удаление сессии убирает её из папки, а закрытие проекта удаляет его папки. В VS Code папки остаются в расширении и не shared.

## Окружение проекта

Когда инструменты проекта берутся из direnv, devenv или Nix shell, Git-хуки, терминал и [project actions](/ru/project-actions/) не находят их сами. Откройте **Настройки → Проекты**, выберите проект и в разделе **Environment**:

- добавьте переменные, нужные только этому проекту
- или задайте **команду окружения**, которая их выводит, например `direnv export json` или `devenv print-dev-env --json`

Команда выполняется в папке проекта, а для worktree — в его собственной папке. Она выполняется повторно при коммите, открытии терминала или запуске действия, когда с прошлого запуска прошло несколько минут, а кнопка **Run again** запускает её сразу. Просто открытый проект её не запускает. Под полем видно, сколько переменных добавил последний запуск, или почему он не удался. Неудачный запуск ничего не добавляет, а Git и терминал продолжают работать без него.

Эти переменные передаются Git, терминалу и действиям проекта поверх переменных из **Настройки → Общие → Переменные окружения** (см. [Environment variables](/ru/environment/#переменные-для-opencode-git-и-терминала)). OpenCode обслуживает все проекты из одного процесса, поэтому переменных проекта он не получает: то, что нужно агенту, поместите в общий список.

Команда принадлежит только вам. Она не читается из репозитория, поэтому клонированный репозиторий не может заставить OpenChamber что-либо выполнить.
