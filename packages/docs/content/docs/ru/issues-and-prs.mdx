# Issues и PR

Доска **Issues и PR** — это отдельная страница со списком issues и pull request проекта в GitHub, GitLab, Gitea, Forgejo или Gerrit (merge request в GitLab, changes в Gerrit, у которого нет issues) либо ваших issues Linear. Выберите элемент, и его превью откроется рядом со списком. Просмотр другого проекта здесь не меняет проект, на котором находится остальное приложение.

## Открытие доски

- Нажмите значок pull request в заголовке боковой панели, рядом с запланированными задачами и архивом.
- Выберите **Issues и PR** в палитре команд.
- Нажмите <kbd>⌘K</kbd>, затем <kbd>B</kbd> (<kbd>Ctrl+K</kbd>, затем <kbd>B</kbd> в Windows и Linux). Те же клавиши закрывают её.

На телефоне нажмите кнопку pull request в подвале меню сессий. В расширении VS Code доски нет.

Доска открывается заново на проекте, вкладке и команде, где вы её оставили.

## Поиск элементов

Всё собрано в одной строке панели инструментов. Слева — выбор проекта, со значками проектов и поиском. Рядом переключайтесь между **Issues**, **Pull request** и **Linear**. Issues и pull request берутся с собственного хоста проекта: GitHub, GitLab, Gitea, Forgejo, Gerrit или хост, который добавляет [расширение](/ru/extensions/#расширение-как-git-хост). Вкладка **Linear** появляется только после подключения Linear. Проект ни на одном из этих хостов показывает только эту вкладку или сообщает, что перечислять нечего. Remote на псевдониме хоста из `~/.ssh/config`, например `github.com-work`, не считается ни одним из них.

Второй выбор рядом с выбором проекта определяет, что перечисляет доска, и появляется, когда папка содержит больше одного репозитория. В папке, которая сама не Git-репозиторий, но содержит репозитории внутри, пункт **Все репозитории** идёт первым и выбран по умолчанию: доска перечисляет вместе issues и pull request каждого репозитория GitHub в папке, и каждая строка называет свой репозиторий. Поиск работает по всем сразу, включая вставленную ссылку или номер. Заметка над списком говорит, сколько репозиториев не включено, например один в GitLab, Gitea, Forgejo или Gerrit либо один, который не может прочитать ни одна подключённая учётная запись, а её меню показывает какие и почему. Выберите один репозиторий, чтобы перечислить только его.

Папка, которая сама является Git-репозиторием, перечисляется сама и остаётся по умолчанию, рядом — её субмодули и вложенные checkout для выбора. Пункт **Все репозитории** там не предлагается, иначе элементы корня перечислялись бы рядом с собой. Доска запоминает выбор для каждого проекта, и он отделён от репозитория, выбранного в виде Git.

Комментарии, метки, ревьюеры и слияние работают в репозитории, которому принадлежит элемент. **Новая сессия** всё равно стартует в папке проекта. **Изменения** и **Обзор** открывают pull request в его собственном репозитории и оставляют репозиторий, выбранный в виде Git, как есть. Запуск работы в worktree для этих элементов пока не предлагается. Ссылка на issue или pull request одного из этих репозиториев открывается в Трекере, прочитанная через этот репозиторий. На телефоне она открывается на доске, которая тоже читает её через собственный репозиторий, оставляя список как был. В расширении VS Code доски нет, поэтому там ничего из этого не меняется.

На **Linear** выбор проекта становится выбором команды: выберите **Все команды** или одну команду. Для проекта только с **Linear** выбор проекта остаётся рядом с выбором команды, чтобы можно было перейти в другой проект. Если подключено больше одной рабочей области Linear, переключайте их из того же меню. Подключение Linear описано в разделе [Интеграции](/ru/integrations/).

Поиск принимает заголовок, номер или вставленную ссылку. Меню фильтров остаётся открытым во время выбора, чтобы можно было комбинировать фильтры.

Для GitHub, GitLab, Gitea, Forgejo и Gerrit:

- Статус: **Открытые**, **Закрытые**, **Все**, а для pull request — **Слитые**
- Люди: **Все**, **Назначены мне**, **Созданы мной**, а для pull request — **Ждут ревью**

Для Linear:

- Статус: **Открытые**, **Все**, **Бэклог**, **К выполнению**, **В работе**, **На ревью**, **Готово**, **Отменено**, **Дубликат**
- Люди: **Все**, **Назначены мне**, **Созданы мной**
- Приоритет: **Все приоритеты**, **Срочный**, **Высокий**, **Средний**, **Низкий**, **Без приоритета**

## Чтение элемента

Превью показывает описание, метки и комментарии. В issue Linear нажмите на пилюлю статуса, чтобы перевести его в другое состояние команды.

В строке **Метки** есть кнопка-карандаш, открывающая список меток репозитория с поиском. Отмечайте их или снимайте отметки. Изменение сохраняется при закрытии списка, поэтому несколько кликов считаются одним изменением. У открытого pull request (merge request в GitLab) также есть строка **Ревьюеры**, работающая так же, с людьми, которые могут ревьюить в репозитории. В GitHub автор pull request не предлагается. У issues Linear нет ни одной из этих строк.

## Комментарии и ревью

Под активностью issue или pull request находится поле комментария. **Комментировать** публикует ваш текст на хосте репозитория, так же как <kbd>⌘</kbd>+<kbd>Enter</kbd> (<kbd>Ctrl</kbd>+<kbd>Enter</kbd> в Windows и Linux). Текст остаётся в поле, пока не опубликован, поэтому неудачная отправка ничего не теряет. Переход к другому элементу очищает поле. У issues Linear его нет.

У открытого pull request (merge request в GitLab) также есть **Одобрить** и **Запросить изменения**, и текст из поля уходит вместе с ревью. **Запросить изменения** требует текста о том, что менять. Ревью относится к коммитам, показанным в превью: если кто-то запушил после, оно отклоняется, а превью обновляется, чтобы вы посмотрели снова. В GitLab **Запросить изменения** работает, когда вы ревьюер merge request, а текст ревью публикуется отдельным комментарием. Если не удаётся только этот комментарий, ревью всё равно засчитывается, а текст остаётся в поле.

У change в Gerrit есть строка для каждой метки проекта, например Code-Review и Verified, с оценками, которые вам разрешено ставить; выберите их и нажмите **Проголосовать**. Ваш текст уходит вместе с голосами как сообщение. Голоса ставятся на последний патчсет, поэтому при чтении более раннего они не предлагаются.

## Начало работы

Действия находятся внизу превью.

- **Новая сессия** открывает новую сессию в проекте с элементом, прикреплённым к полю сообщения. Первое сообщение вы пишете сами.
- **Запустить в worktree…** на issue или **Открыть в worktree…** на pull request открывает диалог создания Worktree с уже выбранным элементом. Pull request открывает собственную ветку. См. [Сессии Worktree](/ru/worktrees/).

Для issue Linear поле **Запустить в** показывает проект, в котором стартует сессия. Это проект, привязанный к команде issue на карточке Linear в [Интеграциях](/ru/integrations/). Без привязки команды это проект по умолчанию, а без него — проект, который доска показывала последним. Для этого issue можно выбрать другой проект прямо там.

## Pull request

Превью pull request также показывает его ветку, размер (добавленные и удалённые строки, изменённые файлы), проверки и ревью. Лента **Активность** выстраивает комментарии, вердикты ревью и newest коммиты в порядке событий. Коммиты, пришедшие подряд, группируются, чтобы было видно, на какие коммиты отвечало ревью.

Рядом с размером две кнопки. **Изменения** открывает дифф pull request в боковой панели, а **Обзор** открывает его [обзор](/ru/walkthrough/). Если приложение находится в другом проекте, оно сначала переключается на проект PR. На телефоне **Изменения** открывает PR во вкладке **Git** ящика рабочей области; **Обзор** — только десктоп и веб.

Внизу **Слить** спрашивает подтверждение перед слиянием и использует ваш обычный метод слияния. У черновика также есть **Готов к ревью**.

В Gerrit превью также показывает топик изменения и то, приватное ли оно или в работе. Если у изменения больше одного патчсета, выбор рядом с **Изменения** определяет, откуда берутся файлы и дифф; сначала выбран последний. **Слить** называется **Отправить**, и кнопка выключена, пока не выполнены требования к отправке изменения, с перечислением невыполненных рядом. **Закрыть** и **Открыть снова** называются **Оставить change** и **Восстановить change**.

У открытого issue или pull request также есть **Закрыть issue** или **Закрыть pull request** (**Закрыть merge request** в GitLab); у закрытого — **Открыть issue снова** или **Открыть pull request снова** (**Открыть merge request снова**). Подтверждения не спрашивают, так как это обратимо. Слитый pull request нельзя закрыть или открыть снова. В GitHub issue закрывается как выполненный.
